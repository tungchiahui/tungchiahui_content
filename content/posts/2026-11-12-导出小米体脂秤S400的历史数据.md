---
title: 使用1Panel和SmartScaleConnect导出小米体脂秤S400的历史数据
---

## 背景

我使用的是**米家体脂秤 S400（国行）**，平时通过 **Mi Fitness（小米运动健康）**查看体重、体脂率、肌肉量等数据。

最近想把这些数据保存到自己的 Linux 服务器，后续再用于个人网站的数据展示。起初尝试了 Home Assistant 的 Xiaomi Miot 插件，虽然能够识别体脂秤，但只生成了设备信息按钮，并没有体重、体脂等传感器。

后来发现开源项目 [SmartScaleConnect](https://github.com/AlexxIT/SmartScaleConnect) 可以直接读取小米云端已有的测量记录，并导出为 JSON，不需要蓝牙网关，也不用申请小米开发者 API。

本文记录我在 **1Panel + Docker** 上实际跑通的过程。测试时 SmartScaleConnect 版本为 `0.4.2`。

## 准备工作

需要具备以下条件：

- 已安装 1Panel，并且 Docker 可以正常使用；
- 一台已经通过 Mi Fitness 同步数据的小米体脂秤 S400；
- 小米账号及密码；
- 服务器能够访问小米相关云端服务。

我这台 S400 的设备型号是：

```text
yunmai.scales.ms103
```

这是**国行 S400** 对应的型号，不能直接照搬给其他型号。项目 README 也明确列出了这个型号的 Mi Fitness 读取方式。

## 创建配置目录

进入 **1Panel → 文件**，创建目录：

```text
/opt/scaleconnect
```

然后在目录内新建 `scaleconnect.yaml` 文件，填写：

```yaml
sync_s400:
  from: mifitness 1234567890 YOUR_XIAOMI_PASSWORD yunmai.scales.ms103
  to: json /config/s400.json
```

这里的几个参数分别代表：

- `mifitness`：从小米运动健康的数据源读取；
- `1234567890`：示例小米账号 ID，替换为**自己的数字小米 ID**；
- `YOUR_XIAOMI_PASSWORD`：替换为小米账号登录密码；
- `yunmai.scales.ms103`：国行 S400 的设备型号；
- `/config/s400.json`：容器内 JSON 输出路径。

我实际使用数字小米 ID 登录成功，并不需要一定改成邮箱。

**注意：配置文件含有账号密码，不要提交到公开 Git 仓库。**

## 在1Panel部署Docker容器

打开 **1Panel → 容器 → 编排 → 创建编排**，名称可以填写 `smartscaleconnect`。

粘贴以下 Docker Compose 配置：

```yaml
services:
  smartscaleconnect:
    image: alexxit/smartscaleconnect:latest
    container_name: smartscaleconnect
    restart: unless-stopped
    environment:
      TZ: Asia/Shanghai
    volumes:
      - /opt/scaleconnect:/config
    command:
      - scaleconnect
      - -c
      - /config/scaleconnect.yaml
      - -r
      - 6h
```

保存并启动容器。

几个关键点：

- `volumes` 将宿主机 `/opt/scaleconnect` 映射到容器 `/config`，生成的 JSON 可以直接在 1Panel 文件管理器中查看；
- `-c` 指定配置文件位置；
- `-r 6h` 表示每隔 6 小时重新同步一次，可以按需求调整；
- 不需要开放端口，因为程序是主动访问云端并写入本地文件。

这里特意指定了 `command`。项目 Docker 镜像默认启动脚本使用交互模式，而本次需要让程序主动读取磁盘中的 YAML 配置。

## 解决小米账号登录报错

第一次启动容器后，我在 1Panel 的容器日志里看到了：

```text
scaleconnect version 0.4.2
sync_s400: load data error: Get "": unsupported protocol scheme ""
```

这个报错看起来像网络地址错误，但项目的 [GitHub Issue #4](https://github.com/AlexxIT/SmartScaleConnect/issues/4) 中有人遇到过相同问题，作者确认其中一个原因是**小米账号需要二次验证（2FA）**，程序没能直接完成登录。

解决思路是：**先通过能完成小米账号验证的工具获取云端授权 Token，再交给 SmartScaleConnect 使用。**

### 获取小米云端Token

这里有两种方法：**XiaomiGateway3** 和 **go2rtc**。两者的目的都是完成小米账号验证，获取后续供 SmartScaleConnect 使用的**小米云端 Token**，并不是通过它们直接读取体脂秤。

**我实际使用的是 XiaomiGateway3，成功获取 Token 后解决了前面的登录报错。** 如果没有 Home Assistant，也可以选择 go2rtc。

#### 方法一：XiaomiGateway3（我实际使用的方法）

[XiaomiGateway3](https://github.com/AlexxIT/XiaomiGateway3) 是 AlexxIT 开发的 Home Assistant 第三方集成。这里借用它的**小米云端登录功能**获取 Token，不需要把 S400 接入 HA，也不需要为了获取 Token 购买实体网关。

1. 打开 Home Assistant，进入 **HACS → 集成**，搜索并安装 **XiaomiGateway3**；如果搜索不到，可按项目 README 的方法添加或手动安装。
2. 按提示重启 Home Assistant，然后进入 **设置 → 设备与服务 → 添加集成**，选择 **Xiaomi Gateway3**。
3. 选择**小米云端（Cloud）账号登录**，用自己的小米账号登录，并按提示完成短信、邮箱或其他安全验证。这里只需要云端账号授权，不需要继续配置实体网关。
4. 登录成功后，打开 Home Assistant 配置目录中的：

   ```text
   /config/.storage/core.config_entries
   ```

   如果 HA 通过 Docker 部署，需要先找到宿主机映射到容器 `/config` 的实际路径，再通过 1Panel 文件管理器打开对应文件。例如，宿主机挂载目录是 `/opt/homeassistant/config`，文件就在 `/opt/homeassistant/config/.storage/core.config_entries`。
5. **在文件中搜索 `xiaomi` 或 `xiaomi_gateway3`**，定位刚刚添加的集成配置，找到对应账号保存的 `token` 字段，复制其**完整值**。

这里最容易搞错的是 Token：文件里可能有多处包含 `token` 的内容，要找的是 **XiaomiGateway3 云端账号配置中的长 Token**，不是某个设备的 LAN Token、蓝牙密钥或其他集成的 Token。作者在 [SmartScaleConnect Issue #4](https://github.com/AlexxIT/SmartScaleConnect/issues/4) 中专门提醒过，正确的云端 Token 很长，内部可能含有冒号。

`.storage/core.config_entries` 是 HA 的内部配置文件，**只读查看、复制所需字段即可，不要修改原文件，更不要把整个文件发给别人**。

#### 方法二：go2rtc（不依赖 Home Assistant）

如果没有安装 Home Assistant，可以使用 [go2rtc 的小米云端登录功能](https://github.com/AlexxIT/go2rtc/blob/master/internal/xiaomi/README.md) 获取 Token。这个功能虽然原本是为小米摄像头准备的，但也可以用于完成小米账号验证。

1. 安装并运行支持该功能的 **go2rtc**，打开它的 WebUI。
2. 进入 **Add → Xiaomi**，使用小米账号和密码登录。
3. 如有需要，按提示完成邮箱或短信验证码、图片验证码等验证。
4. 登录成功后，查看 go2rtc 的配置文件（通常为 `go2rtc.yaml`，具体位置取决于部署时的挂载目录），找到生成的 `xiaomi` 配置。

配置内容大致如下，数字 ID 和 Token 均为示例：

```yaml
xiaomi:
  1234567890: V1:YOUR_LONG_CLOUD_TOKEN
```

这里：

- `1234567890` 是**小米账号 UID**；
- `V1:YOUR_LONG_CLOUD_TOKEN` 是 go2rtc 保存的**云端 Token**；
- 写入 SmartScaleConnect 时，需要将两部分组合为 `1234567890:V1:YOUR_LONG_CLOUD_TOKEN`。

**注意：**如果从 XiaomiGateway3 复制出来的 Token 已经包含 `UID:V1:...`，就直接使用完整原值，**不要再重复添加 UID**。

无论使用哪种方法，最终都要把 Token 写入下面的 `scaleconnect.json`。整个过程中不要公开账号密码、验证码或完整 Token。

### 创建scaleconnect.json

回到 **1Panel → 文件 → `/opt/scaleconnect`**，创建或编辑：

```text
/opt/scaleconnect/scaleconnect.json
```

文件内容：

```json
{
  "xiaomi:1234567890": "1234567890:V1:YOUR_LONG_CLOUD_TOKEN"
}
```

注意三个位置：

- JSON 的 Key 为 `xiaomi:` 加上**配置文件使用的同一个登录账号**；
- Value 前面的数字是小米账号 UID；
- `V1:...` 是完整的云端授权 Token，不能只截取一部分。

我在 `scaleconnect.yaml` 中直接使用数字小米 ID，并通过 **XiaomiGateway3** 获取云端 Token，因此这里的 Key 也使用数字 ID，最终成功同步。

如果使用邮箱登录，Key 应相应改成 `xiaomi:你的登录邮箱`。

这份 JSON 是授权凭据文件，不是最终导出的称重记录文件。建议在服务器终端设置访问权限：

```bash
chmod 600 /opt/scaleconnect/scaleconnect.yaml
chmod 600 /opt/scaleconnect/scaleconnect.json
```

## 重新运行并检查结果

保存两个配置文件后，回到 1Panel 的容器页面，重启 `smartscaleconnect`，再查看日志。

我这里重新运行后得到：

```text
2026/11/12 12:42:54 scaleconnect version 0.4.2
2026/11/12 12:42:54 sync_s400: OK
```

这说明 `sync_s400` 任务已正常执行。接着进入 **1Panel → 文件 → `/opt/scaleconnect`**，检查是否出现：

```text
/opt/scaleconnect/
├── scaleconnect.yaml    # 数据源与输出配置
├── scaleconnect.json    # 小米云端授权凭据
└── s400.json            # 导出的测量记录
```

打开 `s400.json`，里面是一组按测量时间记录的数据。下面是**脱敏后的示例数据**：

```json
[
  {
    "Date": "2026-11-12T07:20:48+08:00",
    "Weight": 75.2,
    "BMI": 23.7,
    "BodyFat": 20.0,
    "MuscleMass": 56.0,
    "SkeletalMuscleMass": 30.5,
    "BodyWater": 53.0,
    "Height": 178,
    "User": "example"
  }
]
```

常见字段包括：

| 字段 | 含义 |
| --- | --- |
| `Date` | 测量时间（带时区） |
| `Weight` | 体重，kg |
| `BMI` | 体重指数 |
| `BodyFat` | 体脂率，% |
| `MuscleMass` | 肌肉量，kg |
| `SkeletalMuscleMass` | 骨骼肌量，kg |
| `BodyWater` | 身体水分，% |
| `VisceralFat` | 内脏脂肪等级 |
| `HeartRate` | 心率，次/分钟 |

**并不是每条记录都有全部字段**：例如，部分测量只有体重和 BMI；有些指标只出现在特定来源的记录中。因此后续处理 JSON 时，应当允许字段缺失。

## 总结

最终数据获取流程如下：

```text
小米体脂秤 S400
    ↓
Mi Fitness 同步到小米云端
    ↓
SmartScaleConnect 定时读取
    ↓
/opt/scaleconnect/s400.json
```

对于我这台国行 S400，实测可以通过 **1Panel + Docker + SmartScaleConnect** 导出历史体重及身体成分记录，不需要额外购买 ESP32，也不必申请小米官方开发者接口。

需要注意的是，SmartScaleConnect 使用第三方实现的云端访问方式，未来可能受到小米登录机制或接口变动影响。`scaleconnect.json` 中的授权凭据和导出的健康记录都应妥善保管，**不要直接把整个目录映射成公开网站目录**。

后续如果需要在个人网站展示趋势，可以再由网站后端读取这份 JSON，或者导入数据库进行分析。
