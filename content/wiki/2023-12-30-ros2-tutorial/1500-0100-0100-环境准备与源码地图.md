> 本套教程只使用 ROS 2 Humble。先准备能重复运行的环境，再开始读源码；学习工作区由你自己创建。

## 本节目标

先分清三件事：容器提供运行环境；工作区保存你写的包；源码阅读目录保存框架实现。安装一个软件包，不等于获得它完整的 `.cpp` 源码。

本教程编写时检查的容器是 `ysu_ros_humble`，系统为 Ubuntu 22.04，GCC 11.4。容器最初没有安装 ros2_control 核心包，已经为教程验证补齐。你仍应执行下面的检查，理解依赖从哪里来。

## 示例 1：进入容器并检查 ROS 版本

下面两行在宿主机执行：

```bash
docker start ysu_ros_humble
docker exec -it ysu_ros_humble bash
```

从这里开始，除非明确标注，命令都在容器里执行：

```bash
source /opt/ros/humble/setup.bash
printenv ROS_DISTRO
lsb_release -ds
g++ --version
ros2 pkg prefix controller_manager
```

预期版本是 `humble`。最后一条若报找不到包，继续安装依赖；若找到路径，记住它指向哪个安装空间。

## 示例 2：安装基础依赖

下面按容器内 root 用户书写；普通用户执行安装命令时加 `sudo`。

```bash
apt-get update
apt-get install -y ros-humble-ros2-control ros-humble-ros2-controllers \
  ros-humble-xacro ros-humble-robot-state-publisher \
  ros-humble-rviz2 ros-humble-joint-state-publisher-gui \
  python3-colcon-common-extensions python3-rosdep git ripgrep
```

仿真依赖留到第 1400 篇，串口依赖留到第 2100 篇。先让最小控制系统运行起来。

## 示例 3：由你创建官方实例工作区

本套教程使用两个工作区：`~/ros2_control_demos_ws` 运行官方实例；`~/ros2_control_humble_ws` 从第 0400 篇开始保存你亲手编写的包。它们都是你学习时执行命令创建的。

```bash
mkdir -p ~/ros2_control_demos_ws/src
cd ~/ros2_control_demos_ws/src
git clone --branch humble https://github.com/ros-controls/ros2_control_demos.git
cd ros2_control_demos
git checkout c273b1316cce043c252c593dc6a232ea57174690
cd ~/ros2_control_demos_ws
rosdep update --rosdistro humble
rosdep install --from-paths src --ignore-src -r -y --rosdistro humble
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-up-to \
  ros2_control_demo_example_1 ros2_control_demo_example_2 \
  ros2_control_demo_example_3 ros2_control_demo_example_9 \
  --cmake-args -DBUILD_TESTING=OFF
source install/setup.bash
```

如果提示 rosdep 尚未初始化，先执行一次 `rosdep init`，再执行 `rosdep update`。不要重复初始化已经存在的配置。

这里用 `--packages-up-to`，会包含工作区内的依赖包。当前 demos 中有 `ros2_control_demo_test_utils`，只选择 example_1 而遗漏依赖会导致构建失败；即使关闭测试，也应让 colcon 正确解析依赖。

## 示例 4：下载供阅读的框架源码

阅读目录与 `src` 分开，避免 colcon 无意间编译整套框架并覆盖发行包。

```bash
mkdir -p ~/ros2_control_humble_reference
cd ~/ros2_control_humble_reference
git clone --depth 1 --branch 2.54.3 https://github.com/ros-controls/ros2_control.git
git clone --depth 1 --branch 2.54.1 https://github.com/ros-controls/ros2_controllers.git
git clone --depth 1 --branch 2.15.1 https://github.com/ros-controls/realtime_tools.git
git clone --depth 1 --branch 4.9.0 https://github.com/ros-controls/control_msgs.git
git clone --depth 1 --branch 0.7.21 https://github.com/ros-controls/gz_ros2_control.git
```

| 仓库 | 本教程采用版本 | 首先阅读的位置 |
|---|---|---|
| ros2_control | 2.54.3 | controller_manager、hardware_interface、controller_interface |
| ros2_controllers | 2.54.1 | forward_command_controller、joint_trajectory_controller、diff_drive_controller |
| realtime_tools | 2.15.1 | realtime_buffer.hpp |
| control_msgs | 4.9.0 | control_msgs/action/FollowJointTrajectory.action |
| gz_ros2_control | 0.7.21 | gz_ros2_control/src、gz_ros2_control_demos |

这些是本次验证使用的版本，不代表所有历史 Humble 安装都具有相同 API。如果你的安装版本不同，先查看差异，再使用匹配的标签。

```bash
dpkg-query -W ros-humble-ros2-control ros-humble-ros2-controllers \
  ros-humble-realtime-tools ros-humble-control-msgs
ros2 pkg prefix hardware_interface
```

## 新终端的统一约定

每个终端都要 source。运行官方例子时 source demos 工作区；运行自编工程时 source learning 工作区。不要在 `.bashrc` 中同时叠加不相关的机器人工作区。一个 ROS domain 中一次只运行一个本教程机器人，避免多个 `/controller_manager` 和 `/joint_states` 相互干扰。

本次验证使用独立 domain 87；你可以在所有相关终端统一设置 `export ROS_DOMAIN_ID=87`。数字不是教程逻辑的一部分，关键是各终端保持一致。

## 本节总结

`source` 决定当前终端能找到哪一套包；`colcon build` 产生安装空间；pluginlib 从安装空间查找插件。下载了源码却没有构建、安装和 source，系统不会自动使用它。

参考：[Humble 官方文档](https://control.ros.org/humble/index.html)、[官方 demos 安装说明](https://control.ros.org/humble/doc/ros2_control_demos/doc/index.html)。
