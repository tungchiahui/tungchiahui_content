## BehaviorTree.CPP v4.10.0 学习路线

> 官方入口：[BehaviorTree.CPP 文档](https://www.behaviortree.dev/docs/intro)、[4.10.0 源码](https://github.com/BehaviorTree/BehaviorTree.CPP/tree/4.10.0)、[版本更新记录](https://github.com/BehaviorTree/BehaviorTree.CPP/blob/4.10.0/CHANGELOG.rst)。

本组固定使用 **BehaviorTree.CPP 4.10.0、C++20、Ubuntu 22.04 和 VSCode CMake Tools**。库自己的源码最低使用 C++17，练习程序沿用现有 C++20 模板。官方网页当前版本标签不一定与 4.10.0 相同，函数声明、控制节点行为和构建开关以标签源码与实际运行结果为准。

行为树组织“检查什么、选择哪个方案、怎样组合任务”。节点具体做什么，由 C++ 实现；XML 将已注册的节点组织成树，主程序通过 tick 推进执行。Groot2 用于编辑结构、观察状态和回放日志。

## 分别保留两个版本的练习工程

v4 练习使用 `bt4_first_tree`、`bt4_ports`、`bt4_running`、`bt4_mission`、`bt4_script`、`bt4_updates` 和 `bt4_groot`。每篇从前一工程复制副本、重命名，清理副本旧 build/install，再替换指定文件；v3 原工程保留供对照。

Configure 优先寻找精确的 4.10.0 安装包，找不到时获取固定标签源码。依赖模块统一保存在 `cmake/BehaviorTree.cmake`。Ubuntu 22.04 可以沿用 CMake 3.22.1，不需要为这些练习升级 CMake。

本组先写独立 CMake 程序。需要接入 ROS 2/Nav2 时，再检查调用方、执行器和插件采用的 BT 版本；不要通过替换某个系统库文件来尝试完成整个系统迁移。

## 新能力分别解决什么问题

| 需求 | 在哪里学习 |
| --- | --- |
| 在运行期间重新检查任务是否允许 | 持续任务与中止；脚本篇对照 `_while` |
| 在 XML 中初始化或修改简单数据 | Script 与前后置条件 |
| 多层子树访问共享外部数据 | 全局 Blackboard |
| 判断条目是否被重新写入，而不只是比较值 | 数据更新序号与 `getInputStamped()` |
| 观察节点为何成功、失败或被中止 | Groot2 实时状态与日志回放 |

全局 Blackboard 与时间戳能力来自 4.6 阶段，脚本等能力来自更早的 v4；这里讲的是 **4.10.0 可使用的能力**，不会把它们全部描述成 4.10.0 首次加入。

## 本组验证范围

完整程序已在 Ubuntu 22.04 的 Humble 容器中，以 CMake 3.22.1、GCC 11.4 和 C++20 编译运行。依赖模块分别验证了固定 4.10.0 源码嵌入与精确安装包查找；源码验证使用已下载并核对哈希的标签内容。迁移最小程序输出的库版本为 4.10.0。

已检查同步示例、端口固定值与默认值、缺失或错误输入、条件中止、主动停止、普通与响应式 Sequence、两段导航重试、错误子树映射、脚本跳过与失败、全局数据重复读取及同值重新写入。Groot2 的模型加载、编辑、实时连接和成功／中止日志读取也已验证。

验证范围是教程的独立模拟程序，尚未将真实 ROS 2 Action 或 Nav2 接入这些示例。截图预留供学习时补齐，不表示读者已经完成相应实践。
