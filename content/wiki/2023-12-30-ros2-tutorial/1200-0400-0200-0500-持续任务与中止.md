## 让导航任务跨越多次 tick

> 对应 BehaviorTree.CPP 3.8 官方文档：[Reactive and Asynchronous behaviors](https://www.behaviortree.dev/docs/3.8/tutorial-basics/tutorial_04_sequence/)。实现细节参考 3.8.7 的 [action_node.cpp](https://github.com/BehaviorTree/BehaviorTree.CPP/blob/3.8.7/src/action_node.cpp)、[reactive_sequence.cpp](https://github.com/BehaviorTree/BehaviorTree.CPP/blob/3.8.7/src/controls/reactive_sequence.cpp) 和 [bt_factory.h](https://github.com/BehaviorTree/BehaviorTree.CPP/blob/3.8.7/include/behaviortree_cpp_v3/bt_factory.h)。

前两篇实践分别完成了最小行为树和节点间的数据传递。如果还没有运行，可以先完成它们，再进入本篇。本篇仍使用模拟数据，集中解决一个问题：**导航还没结束时，节点怎样立即返回，后面怎样继续检查，以及外部条件变化后怎样中止它。**

为了看清生命周期，本篇暂时用 `loading_area` 这样的字符串表示目标位置。导航进度由计数器模拟：开始时返回 `RUNNING`，接下来经过三次运行检查才到达。这里的“三次”表示回调调用次数，实际耗时取决于主程序驱动频率。

```text
ReactiveSequence
├── NavigationAllowed   每次根 tick 都重新检查是否允许导航
└── NavigateToGoal      开始一次任务，后续 tick 检查进度
                         ├── 未完成：RUNNING
                         ├── 已到达：SUCCESS
                         └── 被中止：执行 onHalted()
```

## 用三个回调管理一个持续任务

`SyncActionNode` 用于一次调用就能给出结果的动作，不能用它返回 `RUNNING`。持续任务使用 `StatefulActionNode`，实现下面三个回调：

| 回调 | 调用时机 | 本例做什么 | 返回值 |
| --- | --- | --- | --- |
| `onStart()` | 节点从 `IDLE` 开始执行 | 读取目标、初始化进度，模拟发送请求 | `RUNNING`、`SUCCESS` 或 `FAILURE` |
| `onRunning()` | 当前节点为 `RUNNING`，再次收到 tick | 检查一次进度，报告是否完成 | `RUNNING`、`SUCCESS` 或 `FAILURE` |
| `onHalted()` | 正在 `RUNNING` 的节点被中止 | 取消当前任务、清理本次执行状态 | `void` |

三个回调都**没有函数参数**，由 `StatefulActionNode` 在对应时机调用，不需要在 `main()` 中直接调用。它们的声明分别是 `BT::NodeStatus onStart() override`、`BT::NodeStatus onRunning() override` 和 `void onHalted() override`；`override` 表示实现基类规定的虚函数。回调通过当前节点的 `getInput()` 读取输入，通过对象成员保存执行进度。

`onStart()` 返回 `RUNNING` 后，下一次 tick 才进入 `onRunning()`；运行期间不会每次都重新调用 `onStart()`。两个有返回值的回调都不能返回 `IDLE`。

`StatefulActionNode` 本身不会自动创建工作线程。本例的回调都在主程序驱动行为树的线程里执行，所以每次回调要尽快返回。真实导航可以在 `onStart()` 中发送一次请求，在 `onRunning()` 中检查请求结果，在 `onHalted()` 中发起取消。

### src/main.cpp

用下面的完整程序替换 `src/main.cpp` 的原有内容，再保存。先保留 `cancel_after_two_ticks = false`，运行正常完成的情况。

```cpp
#include "behaviortree_cpp_v3/bt_factory.h"

#include <chrono>
#include <iostream>
#include <stdexcept>
#include <string>

class NavigationAllowed : public BT::ConditionNode
{
public:
    NavigationAllowed(const std::string& name, const BT::NodeConfiguration& config)
        : BT::ConditionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {BT::InputPort<bool>("allowed")};
    }

    BT::NodeStatus tick() override
    {
        auto allowed = getInput<bool>("allowed");
        if (!allowed)
        {
            throw BT::RuntimeError("Cannot read input [allowed]: ", allowed.error());
        }
        std::cout << "[NavigationAllowed] allowed="
                  << (allowed.value() ? "true" : "false") << '\n';
        return allowed.value() ? BT::NodeStatus::SUCCESS : BT::NodeStatus::FAILURE;
    }
};

class NavigateToGoal : public BT::StatefulActionNode
{
public:
    NavigateToGoal(const std::string& name, const BT::NodeConfiguration& config)
        : BT::StatefulActionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {BT::InputPort<std::string>("goal"),
                BT::InputPort<int>("ticks", 3, "完成导航所需的 onRunning 调用次数")};
    }

    BT::NodeStatus onStart() override
    {
        auto goal = getInput<std::string>("goal");
        auto ticks = getInput<int>("ticks");
        if (!goal)
        {
            throw BT::RuntimeError("Cannot read input [goal]: ", goal.error());
        }
        if (!ticks)
        {
            throw BT::RuntimeError("Cannot read input [ticks]: ", ticks.error());
        }
        if (goal.value().empty() || ticks.value() < 1)
        {
            throw std::runtime_error("goal must not be empty and ticks must be positive");
        }

        goal_ = goal.value();
        required_ticks_ = ticks.value();
        completed_ticks_ = 0;
        // 真实导航通常在这里发送一次请求，本例只保存模拟任务状态。
        std::cout << "[NavigateToGoal] start goal=" << goal_ << '\n';
        return BT::NodeStatus::RUNNING;
    }

    BT::NodeStatus onRunning() override
    {
        // 每次只检查一步，立即把执行权交回行为树。
        ++completed_ticks_;
        std::cout << "[NavigateToGoal] progress=" << completed_ticks_
                  << '/' << required_ticks_ << '\n';
        if (completed_ticks_ >= required_ticks_)
        {
            std::cout << "[NavigateToGoal] arrived goal=" << goal_ << '\n';
            return BT::NodeStatus::SUCCESS;
        }
        return BT::NodeStatus::RUNNING;
    }

    void onHalted() override
    {
        // 真实导航在这里取消请求、停止当前任务并清理资源。
        std::cout << "[NavigateToGoal] halted goal=" << goal_
                  << ", progress=" << completed_ticks_ << '\n';
        completed_ticks_ = 0;
    }

private:
    std::string goal_;
    int required_ticks_ = 0;
    int completed_ticks_ = 0;
};

int main()
{
    // 先用 false 跑通；改为 true 后，在第二次根 tick 后禁止继续导航。
    const bool cancel_after_two_ticks = false;

    try
    {
        BT::BehaviorTreeFactory factory;
        factory.registerNodeType<NavigationAllowed>("NavigationAllowed");
        factory.registerNodeType<NavigateToGoal>("NavigateToGoal");

        auto blackboard = BT::Blackboard::create();
        blackboard->set("navigation_allowed", true);
        auto tree = factory.createTreeFromFile(BT_XML_PATH, blackboard);

        BT::NodeStatus result = BT::NodeStatus::RUNNING;
        int tick_count = 0;
        while (result == BT::NodeStatus::RUNNING)
        {
            std::cout << "--- tick " << ++tick_count << '\n';
            result = tree.tickRoot();
            std::cout << "Root returned: " << BT::toStr(result) << '\n';
            if (result != BT::NodeStatus::RUNNING)
            {
                break;
            }

            if (cancel_after_two_ticks && tick_count == 2)
            {
                blackboard->set("navigation_allowed", false);
                std::cout << "[main] navigation is no longer allowed\n";
            }
            // 等待放在主循环中，节点回调本身不长时间阻塞。
            tree.sleep(std::chrono::milliseconds(100));
        }

        std::cout << "Tree result: " << BT::toStr(result) << '\n';
        return result == BT::NodeStatus::SUCCESS ? 0 : 1;
    }
    catch (const std::exception& error)
    {
        std::cerr << "Error: " << error.what() << '\n';
        return 2;
    }
}
```

`goal_`、`required_ticks_`、`completed_ticks_` 是节点对象的成员，能够跨越多次回调保存当前任务的数据。`main()` 中的 `tick_count` 则统计根节点执行次数，两者含义不同。

### `tree.sleep()` 的参数与作用

前一篇的 `tickRootWhileRunning()` 在库内部等待并重复 tick。本篇需要在两次 tick 之间模拟条件变化，因此把循环写在 `main()` 中，并直接使用 `BT::Tree` 的等待接口：

```cpp
void sleep(std::chrono::system_clock::duration timeout);
```

作用：让驱动树的当前线程等待一段时间，为下一次 tick 留出间隔。唯一的参数 `timeout` 是最长等待时长；`std::chrono::milliseconds(100)` 构造一个表示 **100 毫秒** 的时长对象，可以传给这个参数。这个等待也可以被库的唤醒通知提前结束。

返回值：`void`。`tree.sleep()` 本身不会执行节点，也不会创建导航线程；等待结束后，主程序仍需调用 `tree.tickRoot()`。后者没有参数，返回这一次根 tick 的 `BT::NodeStatus`。本例在结果为 `RUNNING` 时继续循环，在成功或失败时退出。

其余注册、端口和 Blackboard 接口沿用前两篇的含义。例如 `blackboard->set("navigation_allowed", true)` 中，第一个参数是键名，第二个参数是布尔值，模板类型由 `true` 推导为 `bool`；`InputPort<int>("ticks", 3, "...")` 的三个参数依次是端口名、默认值和说明。

> **截图预留：导航正常完成。** 展示程序中关闭取消的设置，以及终端里四次根 tick 的完整输出。

这次执行可以对应到下面的过程：

| 根 tick | 条件结果 | 导航回调 | 本次根节点返回 |
| --- | --- | --- | --- |
| 第一次 | 允许 | `onStart()`，进度初始化为 0 | `RUNNING` |
| 第二次 | 允许 | `onRunning()`，进度为 1/3 | `RUNNING` |
| 第三次 | 允许 | `onRunning()`，进度为 2/3 | `RUNNING` |
| 第四次 | 允许 | `onRunning()`，进度为 3/3，到达 | `SUCCESS` |

正常到达时直接返回 `SUCCESS`，不会因此调用 `onHalted()`。取消回调处理的是运行中的任务被中断，不是所有任务结束时都执行的公共收尾函数。

主程序在 `RUNNING` 时继续 tick，在 `SUCCESS` 或 `FAILURE` 时结束本次任务，并用 `tree.sleep()` 留出等待间隔。等待放在主循环里，节点检查本身保持简短；把几秒钟的等待直接塞进 `onRunning()`，会同时拖慢整棵树对条件变化的响应。

3.8.7 的 `tickRoot()` 在返回终态时还会重置根节点状态，因此应保存它的**返回值**作为本次任务结果。稍后查看 `rootNode()->status()` 时可能已经是 `IDLE`，不能据此否定刚刚返回的 `SUCCESS` 或 `FAILURE`。

## 条件改变后中止正在运行的导航

在 `main()` 中将已有的设置改为：

```cpp
const bool cancel_after_two_ticks = true;
```

保存后 **Build → Launch**。主程序会在第二次根 tick 结束后，将 `navigation_allowed` 改成 `false`，模拟外部系统不再允许继续导航。输出为：

```text
--- tick 1
[NavigationAllowed] allowed=true
[NavigateToGoal] start goal=loading_area
Root returned: RUNNING
--- tick 2
[NavigationAllowed] allowed=true
[NavigateToGoal] progress=1/3
Root returned: RUNNING
[main] navigation is no longer allowed
--- tick 3
[NavigationAllowed] allowed=false
[NavigateToGoal] halted goal=loading_area, progress=1
Root returned: FAILURE
Tree result: FAILURE
```

第三次根 tick 先检查 `NavigationAllowed`。条件失败后，`ReactiveSequence` 中止还在运行的导航，触发 `onHalted()`，并将失败结果返回给主程序。此时导航不会再收到第三次根 tick 对应的运行检查，所以打印的进度仍是 1。

> **截图预留：条件变化触发中止。** 展示 `allowed=false`、`halted` 和最终的 `FAILURE`，并标出 C++ 中启用取消的位置。

本例的取消只是清理模拟计数。对真实机器人，`onHalted()` 中还需要实现对应的取消请求或停止逻辑，行为树本身不会替你完成设备控制。

## 对照 Sequence 怎样处理同一个变化

保持取消设置为 `true`，将 XML 中的 `<ReactiveSequence>` 和 `</ReactiveSequence>` 分别改为 `<Sequence>` 和 `</Sequence>`。保存 XML 后直接 **Launch**，无需手动重新编译 C++。

这次虽然主程序仍会打印 `navigation is no longer allowed`，导航却继续执行到成功。在本次任务的 `RUNNING` 期间，普通 `Sequence` 从正在运行的导航继续，不会每次都重新检查已经成功的前置条件。

| 本例中的行为 | `Sequence` | `ReactiveSequence` |
| --- | --- | --- |
| 正常导航期间检查条件 | 开始时一次 | 每次根 tick |
| 第二次根 tick 后将条件改成 false | 导航继续完成 | 下一次根 tick 中止导航 |
| 是否调用导航的 `onHalted()` | 否 | 是 |
| 这次任务的结果 | `SUCCESS` | `FAILURE` |

> **截图预留：Sequence 对照。** 展示 XML 的控制节点名称、只出现一次的条件检查，以及导航仍然到达的结果。

这个差别发生在一次尚未结束的任务内。普通 `Sequence` 结束并重置后，下一次任务仍会从前面的条件重新开始。

## 主程序主动退出时先停止树

前面的中止由条件失败触发。主程序也可以主动决定停止当前任务，并调用 `tree.haltTree()`，让中止沿树传播。

保持 `cancel_after_two_ticks = true`，将 `main()` 中修改 `navigation_allowed` 的整个 `if` 代码块替换为：

```cpp
            if (cancel_after_two_ticks && tick_count == 2)
            {
                std::cout << "[main] stop requested\n";
                tree.haltTree();
                std::cout << "Tree halted: " << BT::toStr(tree.rootNode()->status()) << '\n';
                return 3;
            }
```

保存后 **Build → Launch**。程序会在第二次根 tick 后直接停止树，输出末尾为：

```text
[main] stop requested
[NavigateToGoal] halted goal=loading_area, progress=1
Tree halted: IDLE
```

这次没有再执行第三次根 tick，也没有让条件返回失败。主程序主动停止任务，并打印停止后的根状态 `IDLE`。示例用退出码 `3` 表示主动停止；正常成功为 `0`，任务失败为 `1`，异常报告为 `2`。

`haltTree()` 会重置节点状态，但不会自动清空 Blackboard，也不会替你重置所有 C++ 成员。本例在 `onStart()` 初始化本次进度，在 `onHalted()` 清理中断时的进度，分别明确处理下一次任务的起点。

### 停止树与查看状态的 API

上面的停止代码使用了三个无参数成员函数：

| 接口 | 所属对象 | 返回值与作用 |
| --- | --- | --- |
| `haltTree()` | `BT::Tree` | 返回 `void`，停止当前树并将节点状态重置为 `IDLE`；运行中的 `StatefulActionNode` 会进入 `onHalted()` |
| `rootNode()` | `BT::Tree` | 返回 `BT::TreeNode*`，指向根节点；空树会返回 `nullptr`，本例已经成功创建树，因此可以访问根节点 |
| `status()` | `BT::TreeNode` | 返回 `BT::NodeStatus`，读取节点当前保存的状态，不执行 tick |

`tree.rootNode()->status()` 先取得根节点指针，再读取状态，最后由 `BT::toStr(...)` 转成字符串用于打印。这里在 `haltTree()` 后读取，所以得到 `IDLE`。注意，3.8.7 的 `tickRoot()` 在返回 `SUCCESS` 或 `FAILURE` 时也会把根节点保存的状态重置为 `IDLE`；判断一次 tick 的执行结果，应使用 `tickRoot()` 的返回值。
