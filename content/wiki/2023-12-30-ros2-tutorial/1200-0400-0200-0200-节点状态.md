## Behavior Tree 的节点状态

> 对应 BehaviorTree.CPP 3.8 官方文档：[Learn the Basic Concepts → Introduction to BTs → Basic Concepts](https://www.behaviortree.dev/docs/3.8/learn-the-basics/BT_basics/)。

在上一节中，我们已经知道：

```text
tick
 ↓
Parent
 ↓
Child
```

子节点执行完成后，会把自己的状态返回给父节点：

```text
Parent
 ↑
status
 ↑
Child
```

BehaviorTree.CPP 中，一个节点被 tick 后，最核心的返回状态有三个：

```cpp
BT::NodeStatus::SUCCESS
BT::NodeStatus::FAILURE
BT::NodeStatus::RUNNING
```

官方规定，节点执行自己的 `tick()` 回调后，要通过这三个状态告诉父节点：

> 这次执行成功了、失败了，还是还没执行完。

---

## SUCCESS：任务成功完成

`SUCCESS` 表示：

> 当前节点负责的任务已经成功完成。

例如一个检查电量的节点：

```cpp
BT::NodeStatus CheckBattery()
{
    // 假设当前电量正常
    bool battery_ok = true;

    if (battery_ok)
    {
        return BT::NodeStatus::SUCCESS;
    }

    return BT::NodeStatus::FAILURE;
}
```

如果：

```cpp
battery_ok == true
```

就返回：

```cpp
BT::NodeStatus::SUCCESS
```

表示：

```text
CheckBattery
    ↓
检查完成
    ↓
电量正常
    ↓
SUCCESS
```

对于这种 Condition，也就是“检查条件”的节点，可以把 `SUCCESS` 理解成：

> 条件满足。

例如：

```text
IsBatteryOK
IsPathClear
IsGoalReached
```

如果条件成立，就返回：

```cpp
SUCCESS
```

但是对于 Action，`SUCCESS` 的含义不是“条件为真”，而是：

> 动作已经成功做完。

例如：

```text
OpenDoor
NavigateToGoal
StopRobot
```

如果任务已经成功完成，同样返回：

```cpp
SUCCESS
```

所以不要简单把：

```text
SUCCESS = true
```

当成永远成立的关系。

更准确的是：

```text
Condition 节点：
SUCCESS ≈ 条件成立

Action 节点：
SUCCESS ≈ 动作成功完成
```

---

## FAILURE：任务失败

`FAILURE` 表示：

> 当前节点没有成功完成自己的任务。

还是刚才的电量检查：

```cpp
BT::NodeStatus CheckBattery()
{
    bool battery_ok = false;

    if (battery_ok)
    {
        return BT::NodeStatus::SUCCESS;
    }

    return BT::NodeStatus::FAILURE;
}
```

因为：

```cpp
battery_ok == false
```

最终：

```text
CheckBattery
    ↓
电量不足
    ↓
FAILURE
```

对于 Condition 节点，可以理解成：

```text
FAILURE ≈ 条件不成立
```

例如：

```text
IsPathClear
```

检测到前面有障碍物：

```cpp
return BT::NodeStatus::FAILURE;
```

但对于 Action 节点，`FAILURE` 通常表示：

> 动作已经结束，但是执行失败。

例如导航节点：

```text
NavigateToGoal
```

可能出现：

```text
路径规划失败
目标不可达
导航服务器返回失败
```

于是：

```cpp
return BT::NodeStatus::FAILURE;
```

因此同样不能把它简单理解成：

```text
FAILURE = false
```

更准确的是：

```text
Condition：
FAILURE ≈ 条件不成立

Action：
FAILURE ≈ 动作执行失败
```

---

## RUNNING：任务还没有完成

`RUNNING` 是机器人 Behavior Tree 中非常重要的状态。

它表示：

> 当前 Action 还需要更多时间才能得到最终结果。

例如：

```text
CheckBattery
```

这种检查可能一瞬间就完成。

但：

```text
NavigateToGoal
```

显然不可能一次 `tick()` 就让机器人瞬移到目标点。

假设机器人导航需要几秒钟。

第一次：

```cpp
NavigateToGoal.tick();
```

时，导航刚刚开始：

```text
发送导航目标
    ↓
机器人开始移动
    ↓
任务还没完成
```

此时就应该返回：

```cpp
BT::NodeStatus::RUNNING
```

而不是一直卡在这个函数里等机器人走到终点。

---

## RUNNING 和之前的非阻塞 update()

这和之前学过的非阻塞 FSM 非常像。

以前不推荐写：

```cpp
void MoveRobot()
{
    StartMoving();

    // 一直卡在这里等任务完成
    while (!GoalReached())
    {
    }

    StopMoving();
}
```

因为这样：

```text
MoveRobot()
    ↓
一直阻塞
    ↓
整个决策系统不能继续运行
```

更合理的方式是周期检查：

```cpp
void update()
{
    if (!GoalReached())
    {
        return;
    }

    StopMoving();
}
```

Behavior Tree 中的 `RUNNING` 就是在表达类似的思想。

例如可以先用 C++ 风格伪代码理解：

```cpp
BT::NodeStatus NavigateToGoal::tick()
{
    // 第一次执行时发送导航任务
    if (!navigation_started)
    {
        StartNavigation();
        navigation_started = true;
    }

    // 导航失败
    if (NavigationFailed())
    {
        navigation_started = false;
        return BT::NodeStatus::FAILURE;
    }

    // 已经到达目标
    if (GoalReached())
    {
        navigation_started = false;
        return BT::NodeStatus::SUCCESS;
    }

    // 还在导航
    return BT::NodeStatus::RUNNING;
}
```

注意这个函数并没有写：

```cpp
while (!GoalReached())
{
}
```

而是每次快速检查一次当前状态。

---

## RUNNING 节点需要继续被 tick

假设导航需要三次检查才完成。

第一次 tick：

```text
NavigateToGoal
    ↓
启动导航
    ↓
还没到
    ↓
RUNNING
```

第二次 tick：

```text
NavigateToGoal
    ↓
检查导航状态
    ↓
还没到
    ↓
RUNNING
```

第三次 tick：

```text
NavigateToGoal
    ↓
检查导航状态
    ↓
已经到达
    ↓
SUCCESS
```

可以表示成：

```text
第 1 次 tick
NavigateToGoal
      ↓
   RUNNING

第 2 次 tick
NavigateToGoal
      ↓
   RUNNING

第 3 次 tick
NavigateToGoal
      ↓
   SUCCESS
```

因此：

```text
RUNNING
```

不是任务成功，也不是任务失败。

它只是告诉父节点：

> 我现在还没做完。

---

## SUCCESS 和 FAILURE 是结束状态

从任务执行角度，可以先把三个状态分成两类：

```text
RUNNING
```

表示：

```text
任务尚未结束
```

而：

```text
SUCCESS
FAILURE
```

都表示：

```text
任务已经结束
```

区别只是结果不同：

```text
SUCCESS
↓
成功结束

FAILURE
↓
失败结束
```

因此一个持续执行的节点，典型状态变化可能是：

```text
RUNNING
   ↓
RUNNING
   ↓
RUNNING
   ↓
SUCCESS
```

也可能：

```text
RUNNING
   ↓
RUNNING
   ↓
FAILURE
```

一旦返回：

```cpp
SUCCESS
```

或者：

```cpp
FAILURE
```

这一次任务就已经得到最终结果。

---

## 状态会影响父节点接下来怎么执行

上一节中写过：

```cpp
NodeStatus Parent::tick()
{
    NodeStatus child_status = Child.tick();

    return child_status;
}
```

现在这段代码就更容易理解了。

父节点执行：

```cpp
NodeStatus child_status = Child.tick();
```

以后，`child_status` 可能是：

```cpp
SUCCESS
FAILURE
RUNNING
```

父节点再根据这个状态决定下一步怎么办。

例如可以抽象成：

```cpp
BT::NodeStatus Parent::tick()
{
    BT::NodeStatus child_status = Child.tick();

    if (child_status == BT::NodeStatus::SUCCESS)
    {
        // 子节点成功以后该怎么办
    }

    if (child_status == BT::NodeStatus::FAILURE)
    {
        // 子节点失败以后该怎么办
    }

    if (child_status == BT::NodeStatus::RUNNING)
    {
        // 子节点还没完成
    }
}
```

具体怎么处理，并不是固定的。

这取决于父节点是什么类型。

例如后面会学到：

```text
Sequence
Fallback
Decorator
```

它们收到相同的：

```text
SUCCESS
FAILURE
RUNNING
```

可能会采取完全不同的行为。

这也是为什么 Behavior Tree 必须通过状态把结果从下往上传。

---

## 一个完整的 tick 流程

假设有：

```text
Mission
└── NavigateToGoal
```

第一次 tick：

```text
外部
 ↓ tick

Mission
 ↓ tick

NavigateToGoal
 ↓

导航开始
 ↓

RUNNING
 ↑

Mission
```

因为导航还没有结束，所以：

```cpp
NavigateToGoal.tick();
```

返回：

```cpp
RUNNING
```

下一轮再次从根节点开始 tick。

如果机器人仍然在移动：

```text
Mission
 ↓ tick

NavigateToGoal
 ↓

RUNNING
 ↑

Mission
```

直到某一次：

```text
Mission
 ↓ tick

NavigateToGoal
 ↓

目标到达
 ↓

SUCCESS
 ↑

Mission
```

因此完整模型就是：

```text
tick 向下

Root
 ↓
Parent
 ↓
Action
```

然后：

```text
状态向上

Root
 ↑
Parent
 ↑
SUCCESS / FAILURE / RUNNING
```

## 不要用 RUNNING 代替阻塞

下面这种写法虽然最后可能返回 `SUCCESS`，但并不是我们想要的 Behavior Tree 异步行为：

```cpp
BT::NodeStatus NavigateToGoal::tick()
{
    StartNavigation();

    // 错误思路：一直堵在 tick() 中
    while (!GoalReached())
    {
        std::this_thread::sleep_for(
            std::chrono::milliseconds(100));
    }

    return BT::NodeStatus::SUCCESS;
}
```

因为一次：

```cpp
tick();
```

可能卡住几秒甚至几十秒。

这样在这段时间里，Behavior Tree 无法正常进行下一轮决策。

正确的思想是：

```cpp
BT::NodeStatus NavigateToGoal::tick()
{
    StartOrCheckNavigation();

    if (GoalReached())
    {
        return BT::NodeStatus::SUCCESS;
    }

    if (NavigationFailed())
    {
        return BT::NodeStatus::FAILURE;
    }

    return BT::NodeStatus::RUNNING;
}
```

让每一次 `tick()` 尽快返回。

这也是 BehaviorTree.CPP 非阻塞、异步 Action 的核心基础。

真正的 `StatefulActionNode`、`onStart()`、`onRunning()`、`onHalted()` 后面再正式学习，现在先理解 `RUNNING` 的语义即可。

---

## ConditionNode 一般不能返回 RUNNING

`ConditionNode` 用于检查条件，不应该改变系统状态，并且**不应该返回 `RUNNING`**。

例如：

```cpp
BT::NodeStatus IsPathClear()
{
    if (path_is_clear)
    {
        return BT::NodeStatus::SUCCESS;
    }

    return BT::NodeStatus::FAILURE;
}
```

一次检查就能得到结果：

```text
道路畅通
→ SUCCESS

道路不通
→ FAILURE
```

而不是：

```text
道路还在检查……
→ RUNNING
```

`RUNNING` 更典型地用于需要时间完成的 Action，例如：

```text
NavigateToGoal
MoveArm
DockRobot
WaitForDoor
```

同步 Action 一次执行后直接结束为 `SUCCESS` 或 `FAILURE`；异步 Action 可以返回 `RUNNING`，后续继续被 tick。

---

## IDLE 是什么

BehaviorTree.CPP 内部还会看到：

```cpp
BT::NodeStatus::IDLE
```

它表示：

> 节点当前还没有在执行，或者已经被重置回初始状态。

例如一个节点还没有收到 tick 时，可以处于：

```text
IDLE
```

之后可能：

```text
IDLE
 ↓ tick
RUNNING
 ↓
RUNNING
 ↓
SUCCESS
```

但要注意：

`IDLE` 和刚才三个状态的用途不同。

节点自己的 `tick()` 回调正常需要返回的是：

```cpp
SUCCESS
FAILURE
RUNNING
```

而不是：

```cpp
IDLE
```

因此现阶段可以这样记：

```text
IDLE
=
还没有开始执行

RUNNING
=
正在执行

SUCCESS
=
成功结束

FAILURE
=
失败结束
```

后面学习 `StatefulActionNode` 时，`IDLE → RUNNING` 的状态变化还会再次出现。

---

## 本节结论

一个节点收到 tick 后，需要告诉父节点自己的执行结果：

```cpp
SUCCESS
FAILURE
RUNNING
```

它们分别表示：

```text
SUCCESS
任务已经成功完成

FAILURE
任务已经失败结束

RUNNING
任务还没有完成
```

对于机器人中的持续任务：

```text
NavigateToGoal
```

典型执行过程是：

```text
第 1 次 tick
RUNNING

第 2 次 tick
RUNNING

第 3 次 tick
RUNNING

...

最终
SUCCESS
```

或者：

```text
最终
FAILURE
```

因此 Behavior Tree 的一个核心执行模型可以进一步写成：

```text
             tick
              ↓
           Parent
              ↓
            Child
              ↓
       执行一次当前逻辑
              ↓
   SUCCESS / FAILURE / RUNNING
              ↑
           Parent
```

其中最需要记住的是：

> **`RUNNING` 表示“这次 tick 还没做完，但函数应该先返回；之后再继续 tick”，而不是让 `tick()` 一直阻塞到任务结束。**

下一部分继续学习 Behavior Tree 的节点类型：

```text
ControlNode
DecoratorNode
ConditionNode
ActionNode
```
