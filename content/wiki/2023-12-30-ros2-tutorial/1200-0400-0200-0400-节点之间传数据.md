## 从外部位姿计算一个任务目标

假设移动机器人当前位姿为 `(1.0, 2.0, 0.0)`，
需要沿当前朝向前进 2 米，
再给目标的 x 坐标增加 0.5 米的示例偏移：

```text
外部程序初始化 Blackboard
├── robot_pose       = Pose2D{1.0, 2.0, 0.0}
└── travel_distance  = 2.0
         ↓
Sequence
├── CalculateGoal    根据起点、朝向和距离计算目标，写入 mission_goal
├── OffsetGoal       读取 mission_goal，修改后写回同一个条目
├── PrintGoal        从 mission_goal 读取计算结果
└── PrintGoal        从 XML 固定文本读取另一组坐标
         ↓
外部程序读取 mission_goal
```

这里的 `Pose2D` 是自行定义的 C++ 结构体，包含 `x`、`y`、`yaw`，不依赖 ROS 消息类型。
位置单位为米，朝向单位为弧度，示例中的坐标使用同一个参考坐标系。

计算时使用：

```text
goal.x   = start.x + distance × cos(start.yaw)
goal.y   = start.y + distance × sin(start.yaw)
goal.yaw = start.yaw
```

起始位姿`(1.0, 2.0, 0.0)`，起始朝向为 0，所以朝前（是x）2米，先得到 `(3.0, 2.0, 0.0)`；
加上 x 偏移后，最终任务目标为 `(3.5, 2.0, 0.0)`。这是坐标计算示例，不包含路径规划、碰撞检查或导航控制。

## 端口名称与 Blackboard 键各管一层

本篇用以下连接传递目标：

```xml
<CalculateGoal start="{robot_pose}" distance="{travel_distance}" goal="{mission_goal}"/>
<OffsetGoal goal="{mission_goal}" offset_x="0.5"/>
<PrintGoal target="{mission_goal}"/>
```

读这段 XML 时，把节点接口和存储位置分开看：

| 名称 | 所属位置 | 作用 |
| --- | --- | --- |
| `CalculateGoal` 的 `goal` | 输出端口 | 计算节点写出目标的接口 |
| `OffsetGoal` 的 `goal` | 双向端口 | 偏移节点读取并更新目标的接口 |
| `PrintGoal` 的 `target` | 输入端口 | 打印节点读取目标的接口 |
| `mission_goal` | Blackboard 键 | 保存这几个端口共同使用的目标数据 |

生产者的端口叫 `goal`，消费者的端口叫 `target`，仍然可以连接，因为 XML 把它们映射到同一个 `{mission_goal}`，而且使用相同的 `Pose2D` 类型。

C++ 中使用的是节点自己的端口名称：`setOutput("goal", ...)` 或 `getInput<Pose2D>("target")`。
将来把 Blackboard 键改为 `delivery_goal`，只需统一调整 XML 中的映射，节点实现不必跟着改名。

### 三种端口方向

| 声明 | 读写方法 | 适合的职责 |
| --- | --- | --- |
| `BT::InputPort<T>` | `getInput<T>()` | 读取起点、距离、目标等输入 |
| `BT::OutputPort<T>` | `setOutput()` | 产生并写出一个结果 |
| `BT::BidirectionalPort<T>` | 先读取，再按需写出 | 读取已有目标，修改后写回 |

双向端口同时提供读写接口；它不会自动完成修改，也不保证条目已经有值。
本例先执行 `CalculateGoal`，再执行 `OffsetGoal`，就是为了在读写目标前先产生有效数据。

`getInput()` 将值读到本地变量，修改这个变量不会直接改变 Blackboard。
偏移节点需要明确调用 `setOutput()` 写回结果。

## XML 文本与 C++ 类型怎样对应

### 数值可以来自固定文本、Blackboard 或默认值

计算节点的距离输入声明为 `double`，下面三种配置对应三种来源：

| XML 配置 | 取值方式 |
| --- | --- |
| `distance="2.0"` | 将固定文本转换成 `double` |
| `distance="{travel_distance}"` | 从 Blackboard 读取对应条目 |
| 省略 `distance` 属性 | 使用节点声明的默认值，本例为 `1.0` |

BehaviorTree.CPP 已经提供常用数值类型的文本转换。
默认值通过 `providedPorts()` 声明；
下面完整程序使用 3.8 的三参数写法 `BT::InputPort<double>("distance", 1.0, "前进距离，单位为米")`。

默认值用于没有显式配置该输入的情况。
如果 XML 已经写成 `{unknown_distance}`，但该条目没有有效值，读取仍会失败，不会自动退回默认值。

### 自定义类型需要约定文本格式

本篇约定 `Pose2D` 的文本格式为三个用分号分隔的实数：

```text
x;y;yaw
2.0;3.0;1.57
```

因此，`<PrintGoal target="2.0;3.0;1.57"/>` 需要把字符串转换成 `Pose2D`。
做法是在 `BT` 命名空间中，为 `convertFromString<Pose2D>()` 提供模板特化，再分别转换三个数值。
特化放在使用该类型声明端口的节点类之前。

两条数据路径有所区别：

```text
C++ 计算出的 Pose2D → setOutput() → Blackboard → getInput<Pose2D>()
                                           直接读取对应类型的值

XML 中的 "2.0;3.0;1.57" → getInput<Pose2D>() → convertFromString<Pose2D>()
                                           先解析文本，再得到值
```

Blackboard 可以保存结构体，不需要把所有数据先转成字符串。
XML 文本转换也不会让任意两个 C++ 类型自动互相兼容；生产者、消费者和外部程序仍应统一数据类型。

### src/main.cpp

```cpp
#include "behaviortree_cpp_v3/bt_factory.h"

#include <cmath>
#include <exception>
#include <iomanip>
#include <iostream>
#include <string>

struct Pose2D
{
    double x;
    double y;
    double yaw;
};

// 统一坐标的打印方式，便于观察每一步的数据
std::ostream& operator<<(std::ostream& stream, const Pose2D& pose)
{
    return stream << '(' << pose.x << ", " << pose.y << ", " << pose.yaw << ')';
}

namespace BT
{
template <>
inline Pose2D convertFromString<Pose2D>(StringView text)
{
    // XML 中的位姿格式为 x;y;yaw，朝向单位为弧度
    const auto parts = splitString(text, ';');
    if (parts.size() != 3)
    {
        throw RuntimeError("Pose2D requires x;y;yaw");
    }

    Pose2D pose{
        convertFromString<double>(parts[0]),
        convertFromString<double>(parts[1]),
        convertFromString<double>(parts[2])};

    if (!std::isfinite(pose.x) || !std::isfinite(pose.y) || !std::isfinite(pose.yaw))
    {
        throw RuntimeError("Pose2D values must be finite");
    }
    return pose;
}
}  // namespace BT

class CalculateGoal : public BT::SyncActionNode
{
public:
    CalculateGoal(const std::string& name, const BT::NodeConfiguration& config)
        : BT::SyncActionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {
            BT::InputPort<Pose2D>("start"),
            BT::InputPort<double>("distance", 1.0, "前进距离，单位为米"),
            BT::OutputPort<Pose2D>("goal")};
    }

    BT::NodeStatus tick() override
    {
        const auto start = getInput<Pose2D>("start");
        const auto distance = getInput<double>("distance");
        if (!start)
        {
            throw BT::RuntimeError("Cannot read input [start]: ", start.error());
        }
        if (!distance)
        {
            throw BT::RuntimeError("Cannot read input [distance]: ", distance.error());
        }
        if (!std::isfinite(distance.value()) || distance.value() < 0.0)
        {
            throw BT::RuntimeError("Input [distance] must be finite and non-negative");
        }

        // 沿起始朝向计算目标，计算结果仍是一个 Pose2D 对象
        const Pose2D& origin = start.value();
        const Pose2D goal{
            origin.x + distance.value() * std::cos(origin.yaw),
            origin.y + distance.value() * std::sin(origin.yaw),
            origin.yaw};

        const auto written = setOutput<Pose2D>("goal", goal);
        if (!written)
        {
            throw BT::RuntimeError("Cannot write output [goal]: ", written.error());
        }
        std::cout << "[CalculateGoal] distance=" << distance.value()
                  << ", goal=" << goal << '\n';
        return BT::NodeStatus::SUCCESS;
    }
};

class OffsetGoal : public BT::SyncActionNode
{
public:
    OffsetGoal(const std::string& name, const BT::NodeConfiguration& config)
        : BT::SyncActionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {
            BT::BidirectionalPort<Pose2D>("goal"),
            BT::InputPort<double>("offset_x", 0.0, "目标在参考坐标系 x 方向的偏移")};
    }

    BT::NodeStatus tick() override
    {
        const auto input = getInput<Pose2D>("goal");
        const auto offset = getInput<double>("offset_x");
        if (!input)
        {
            throw BT::RuntimeError("Cannot read input [goal]: ", input.error());
        }
        if (!offset)
        {
            throw BT::RuntimeError("Cannot read input [offset_x]: ", offset.error());
        }
        if (!std::isfinite(offset.value()))
        {
            throw BT::RuntimeError("Input [offset_x] must be finite");
        }

        // 先修改本地副本，再通过双向端口写回同一个条目
        Pose2D goal = input.value();
        goal.x += offset.value();
        const auto written = setOutput<Pose2D>("goal", goal);
        if (!written)
        {
            throw BT::RuntimeError("Cannot write output [goal]: ", written.error());
        }
        std::cout << "[OffsetGoal] goal=" << goal << '\n';
        return BT::NodeStatus::SUCCESS;
    }
};

class PrintGoal : public BT::SyncActionNode
{
public:
    PrintGoal(const std::string& name, const BT::NodeConfiguration& config)
        : BT::SyncActionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {BT::InputPort<Pose2D>("target")};
    }

    BT::NodeStatus tick() override
    {
        const auto target = getInput<Pose2D>("target");
        if (!target)
        {
            throw BT::RuntimeError("Cannot read input [target]: ", target.error());
        }
        std::cout << "[PrintGoal:" << name() << "] target=" << target.value() << '\n';
        return BT::NodeStatus::SUCCESS;
    }
};

int main()
{
    try
    {
        // 在编辑器中修改这个模拟距离，再构建运行；XML 路径由构建配置提供
        const double distance = 2.0;
        std::cout << std::fixed << std::setprecision(2);

        // 外部程序在创建树之前，准备带有明确 C++ 类型的输入
        auto blackboard = BT::Blackboard::create();
        blackboard->set<Pose2D>("robot_pose", Pose2D{1.0, 2.0, 0.0});
        blackboard->set<double>("travel_distance", distance);

        BT::BehaviorTreeFactory factory;
        factory.registerNodeType<CalculateGoal>("CalculateGoal");
        factory.registerNodeType<OffsetGoal>("OffsetGoal");
        factory.registerNodeType<PrintGoal>("PrintGoal");
        auto tree = factory.createTreeFromFile(BT_XML_PATH, blackboard);

        const BT::NodeStatus result = tree.tickRootWhileRunning();
        std::cout << "Tree result: " << BT::toStr(result) << '\n';
        if (result == BT::NodeStatus::SUCCESS)
        {
            // 树执行后，外部程序可以从同一块 Blackboard 取得输出
            const Pose2D goal = blackboard->get<Pose2D>("mission_goal");
            std::cout << "[main] mission_goal=" << goal << '\n';
        }
        return result == BT::NodeStatus::SUCCESS ? 0 : 1;
    }
    catch (const std::exception& error)
    {
        std::cerr << "Error: " << error.what() << '\n';
        return 2;
    }
}
```

`getInput<T>()` 返回的是带有成功或错误信息的结果；检查有效后，再用 `.value()` 取得值。`setOutput()` 同样有返回结果，本例也进行检查；类型冲突等情况还可能抛出异常，由 `main()` 统一显示。

本例把缺少必要输入、文本格式错误等作为配置或数据错误报告，退出码为 `2`。实际任务中可以根据节点职责选择返回 `FAILURE` 或使用默认值，不必把所有情况都处理成异常。

### 创建、写入和读取 Blackboard 的 API

上一篇介绍了节点内部的 `getInput()` 和 `setOutput()`。
本篇在 `main()` 中直接访问 Blackboard，使用的是另一组接口。
下面列出本例用到的函数原型；声明用于阅读，不用再复制到工程中。

```cpp
// Blackboard 类中的成员声明
static BT::Blackboard::Ptr create(BT::Blackboard::Ptr parent = {});

template<typename T>
void set(const std::string& key, const T& value);

template<typename T>
T get(const std::string& key) const;
```

| 调用 | 参数 | 返回值与作用 |
| --- | --- | --- |
| `BT::Blackboard::create()` | 本例不传参数；可选参数 `parent` 指定父 Blackboard，默认空指针 | 返回 `BT::Blackboard::Ptr`，也就是 `std::shared_ptr<BT::Blackboard>`，用于持有这块 Blackboard |
| `blackboard->set<Pose2D>("robot_pose", Pose2D{1.0, 2.0, 0.0})` | 模板参数 `Pose2D` 指定值类型；第一个参数是键名，第二个参数是要保存的值 | 返回 `void`，创建或更新条目；类型不兼容等错误可能抛出异常 |
| `blackboard->get<Pose2D>("mission_goal")` | 模板参数指定期望读取的类型；唯一的函数参数是键名 | 返回一个 `Pose2D` 值；本例使用的这个重载在键不存在或类型转换失败时抛出异常 |

这里的 `key` 是 **Blackboard 键**。
节点内部的 `getInput("target")`、`setOutput("goal", value)` 接收的则是 **节点端口名**，由 XML 决定它们连接哪个键。

`factory.createTreeFromFile(BT_XML_PATH, blackboard)` 的第一个参数仍是 XML 路径，第二个参数把刚准备好的 Blackboard 交给根树。
这里传递的是共享指针，因此节点执行时读写的就是 `main()` 中持有的同一块数据。
`get<Pose2D>()` 返回值的副本，修改取得的 `goal` 变量不会自动更新 Blackboard；
需要更新时仍应调用 `set()`。

### 带默认值的输入端口与双向端口

本篇第一次使用 `InputPort<T>()` 的三参数重载：

```cpp
template<typename T = void>
std::pair<std::string, BT::PortInfo> InputPort(
    BT::StringView name,
    const T& default_value,
    BT::StringView description);
```

以 `BT::InputPort<double>("distance", 1.0, "前进距离，单位为米")` 为例：

| 项目 | 含义 |
| --- | --- |
| 模板参数 `double` | 输入值的 C++ 类型 |
| 第一个参数 `"distance"` | 节点自己的端口名称，对应 XML 中的 `distance` 属性 |
| 第二个参数 `1.0` | 没有配置该输入时使用的默认值 |
| 第三个参数 | 端口的文字说明，用于描述接口，不参与距离计算 |
| 返回值 | 一项端口声明，由 `providedPorts()` 收集后交给工厂 |

在 3.8.7 中，这个默认值重载需要三个参数；没有说明文字时可以把第三个参数写成 `""`。前面见过的两参数形式 `InputPort<T>(name, description)` 中，第二个参数是说明文字，不能把两种重载混为一谈。

`BT::BidirectionalPort<Pose2D>("goal")` 声明双向端口：模板参数指定 `Pose2D` 类型，第一个参数指定端口名；可选的第二个参数也是说明文字。它同样返回一项端口声明。`OffsetGoal` 随后用 `getInput<Pose2D>("goal")` 取得原值，再用 `setOutput("goal", goal)` 写回修改后的值；声明双向端口本身不会执行读写。

### 拆分文本与转换自定义类型的 API

下面两个接口来自 `BT` 命名空间：

```cpp
std::vector<BT::StringView> splitString(
    const BT::StringView& strToSplit, char delimeter);

template<typename T>
T convertFromString(BT::StringView str);
```

| 调用 | 参数 | 返回值 |
| --- | --- | --- |
| `splitString(text, ';')` | 第一个参数是待拆分的文本；第二个参数是分隔字符 `';'` | `std::vector<BT::StringView>`，本例应得到 x、y、yaw 三个文本片段 |
| `convertFromString<double>(parts[0])` | 模板参数 `double` 指定目标类型；函数参数是一个数值文本片段 | 转换后的 `double`；无效文本会报告转换错误 |
| `convertFromString<Pose2D>(text)` | 模板参数 `Pose2D` 指定自定义类型；函数参数是完整的位姿文本 | 本例特化产生的 `Pose2D`；字段数量错误、数值无效等情况抛出异常 |

`BT::StringView` 是不拥有字符数据的字符串视图，拆分得到的片段仍引用原始文本。本例在转换函数内立即使用它们，不把这些视图保存为节点成员。

`template <>` 表示为 `Pose2D` 提供这个函数模板的特化。节点读取 XML 固定文本时，`getInput<Pose2D>()` 会通过库的转换机制调用它，主程序不需要再手动转换一次；从 Blackboard 读取已经保存的 `Pose2D` 时则直接取得对应类型的值。

### 连续驱动行为树与辅助函数

`tree.tickRootWhileRunning()` 把重复 tick 的循环放在库内部，其原型为：

```cpp
BT::NodeStatus tickRootWhileRunning(
    std::chrono::milliseconds sleep_time = std::chrono::milliseconds(10));
```

唯一的可选参数 `sleep_time` 表示两次 tick 之间的最长等待时间，默认 10 毫秒。本例省略它。
函数先执行一次根 tick；只有结果为 `RUNNING` 时才等待并继续 tick，直到得到最终结果，返回 `BT::NodeStatus`。
本例全部是同步节点，正常情况下第一次根 tick 就得到 `SUCCESS`。

程序中另外几个辅助接口可以按下面理解：

| 写法 | 参数与结果 |
| --- | --- |
| `name()` | 节点成员函数，无参数，返回当前实例名称的 `const std::string&`；本例两个打印节点分别叫 `computed` 和 `literal` |
| `std::isfinite(value)` | 传入一个浮点数，返回 `bool`，检查它是否为有限值 |
| `std::cos(yaw)`、`std::sin(yaw)` | 传入以弧度表示的角度，返回余弦、正弦值，用于分解前进距离 |
| `std::fixed`、`std::setprecision(2)` | 前者设置固定小数格式，后者的参数 `2` 指定显示两位小数；只改变输出格式，不改变 Blackboard 中的数据 |

### trees/mission.xml

```xml
<root main_tree_to_execute="MainTree">
    <BehaviorTree ID="MainTree">
        <Sequence name="goal_pipeline">
            <CalculateGoal start="{robot_pose}"
                           distance="{travel_distance}"
                           goal="{mission_goal}"/>
            <OffsetGoal goal="{mission_goal}" offset_x="0.5"/>
            <PrintGoal name="computed" target="{mission_goal}"/>
            <PrintGoal name="literal" target="2.0;3.0;1.57"/>
        </Sequence>
    </BehaviorTree>
</root>
```

两个 `PrintGoal` 是同一 C++ 类型的不同实例。`name` 帮助区分输出，`target` 则分别配置为 Blackboard 引用和固定文本。

## 输入错误要在读取位置明确处理

本例常见的数据问题可以按发生位置区分：

| 修改 | 发生什么 | 本例的处理 |
| --- | --- | --- |
| 将 `target` 改为 `{unknown_goal}` | 找不到有效的输入值 | `getInput()` 失败，报告读取错误 |
| 将固定坐标改为 `2.0;3.0` | 字段数量不符合约定 | 转换函数报告 `Pose2D requires x;y;yaw` |
| 将距离改为 `distance="far"` | 文本无法转换成 `double` | 读取失败，报告转换错误 |
| 把 `OffsetGoal` 移到 `CalculateGoal` 前面 | 目标还没有被写入 | 读取双向端口失败，后面的节点不再执行 |

这些 XML 对照都在编辑器中修改并保存，再点击 Launch，在集成终端中查看错误信息。

![](https://cdn.tungchiahui.cn/tungwebsite/assets/images/2023/12/30/1792397397830-5f03672f.webp)

工厂可以在创建树时建立端口和条目的关系，但这不代表每个输入已经有业务值。数据是否准备好，仍要看外部初始化与前面节点的执行结果。

外部读取也要使用对应类型。这里调用 `blackboard->get<Pose2D>("mission_goal")`，不能因为打印出来像文本，就改成读取 `std::string`。直接访问 Blackboard 的 `get()` 与节点的 `getInput()` 是不同接口，不应假定它会执行相同的文本转换。

## Blackboard 数据不会随节点状态自动清空

本例在 `CalculateGoal` 中产生目标，在 `OffsetGoal` 中更新目标；树任务结束后，`main()` 仍能读到最终值。
节点结束或被重置到 `IDLE`，不会自动删除这些 Blackboard 条目。

这也意味着，上一次任务留下的值不能自动代表下一次任务已经准备好。
组织重复任务时，应明确哪些输入由外部更新，哪些输出由当前任务重新产生，以及失败后是否允许继续使用已有结果。

本例中的输出节点每次成功执行都会重新写入目标，再由后续节点读取。后面使用子树时，还需要明确不同 Blackboard 范围之间的数据映射；共享一个键的写法不能直接套用到所有子树。
