title: "URDF与控制接口"
---

> 模型中的 joint 定义连接关系，ros2_control 标签中的同名 joint 声明控制接口。两者要对应，但承担不同职责。

## 示例 1：逐项阅读硬件标签

沿用[从零创建学习工作区](/wiki/2023-12-30-ros2-tutorial/1500-0200-0400-cong-ling-chuang-jian-xue-xi-gong-zuo-qu)的完整模型：

| 字段 | 本例 | 解释 |
|---|---|---|
| ros2_control/name | MiniSystem | 组件名称，供硬件生命周期命令使用 |
| ros2_control/type | system | 组件类别 |
| hardware/plugin | mock_components/GenericSystem | pluginlib 查找名称 |
| joint/name | joint1、joint2 | 与模型关节对应 |
| command_interface | position | 控制器可写的目标 |
| state_interface | position、velocity | 控制器与广播器可读的状态 |

完整接口名为 joint1/position，而不是只有 position。硬件组件名、插件查找名、C++ 类名和关节接口名是不同层次的名称。

## 示例 2：查看展开结果

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_control_jazzy_ws/install/setup.bash
```

```bash
cd ~/ros2_control_jazzy_ws

sed -n '1,180p' /tmp/two_joint_expanded.urdf
```

当前是普通 URDF，xacro 仍可处理。仿真章节会加入包路径替换，此时需要先展开。

### 解析过程

```text
XML 字符串
  → parse_control_resources_from_urdf
  → HardwareInfo、关节列表、接口描述与参数
  → 创建硬件组件
  → 根据描述创建接口
```

Jazzy 会检查控制标签中的关节是否存在于机器人模型中。名称错误可能在模型校验阶段就被拒绝，而不是等到发送命令才出问题。

## 示例 3：参数和限制的边界

hardware 下的 param 是给设备后端的配置；YAML 中的控制器参数是给控制器的配置。两者不能因为名称相同就互相替代。

URDF 的 joint limit、控制器的限速参数和设备限幅也不等同。后端应明确自己接受什么命令，不能只写上模型限制就假定任意设备都被保护。

源码：[ros2_control/hardware_interface/src/component_parser.cpp](https://github.com/ros-controls/ros2_control/blob/b7f1a5d420443c7a079f4c81e80d5e39759acf4c/hardware_interface/src/component_parser.cpp)和[ros2_control/hardware_interface/include/hardware_interface/hardware_info.hpp](https://github.com/ros-controls/ros2_control/blob/b7f1a5d420443c7a079f4c81e80d5e39759acf4c/hardware_interface/include/hardware_interface/hardware_info.hpp)。重点观察 InterfaceDescription 怎样保留完整名字与配置。
