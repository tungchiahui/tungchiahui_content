## 把已有节点组合成移动机器人任务

> 对应 BehaviorTree.CPP 3.8 官方文档：[Using SubTrees](https://www.behaviortree.dev/docs/3.8/tutorial-basics/tutorial_05_subtrees/)、[Port Remapping](https://www.behaviortree.dev/docs/3.8/tutorial-basics/tutorial_06_subtree_ports/) 和 [Use multiple XML files](https://www.behaviortree.dev/docs/3.8/tutorial-basics/tutorial_07_multiple_xml/)。实现细节参考 3.8.7 的 [xml_parsing.cpp](https://github.com/BehaviorTree/BehaviorTree.CPP/blob/3.8.7/src/xml_parsing.cpp)、[blackboard.h](https://github.com/BehaviorTree/BehaviorTree.CPP/blob/3.8.7/include/behaviortree_cpp_v3/blackboard.h) 和 [retry_node.cpp](https://github.com/BehaviorTree/BehaviorTree.CPP/blob/3.8.7/src/decorators/retry_node.cpp)。

前面的实践已经分别给出了端口、Blackboard 和持续动作。
本篇把它们组合成一个完整主题：**机器人先确保电量足够，再依次前往取货点和放货点；每段导航允许有限次尝试，成功后报告结果，尝试耗尽后报告任务失败。**

本篇的导航仍用回调计数模拟，充电简化为一次电量更新，全部运行都不需要连接机器人。先完成前面几篇的实践，再运行本篇，便于把注意力集中在任务组织与子树边界上。

```text
MainTree
└── Sequence：一次运输任务
    ├── Fallback：确保电量
    │   ├── BatteryOK
    │   └── ChargeBattery
    └── Fallback：执行任务，或报告失败
        ├── Sequence
        │   ├── SubTree：NavigateLeg，前往取货点
        │   ├── SubTree：NavigateLeg，前往放货点
        │   └── ReportMission
        └── ForceFailure
            └── ReportFailure

NavigateLeg：每次调用都创建自己的节点和局部 Blackboard
└── RetryUntilSuccessful：最多尝试两次
    └── NavigateToGoal：跨多次 tick 检查本次导航
```

电量检查失败时，Fallback 继续执行模拟充电；充电成功后，外层 Sequence 才进入导航。导航序列返回 `RUNNING` 时，任务 Fallback 也返回 `RUNNING`，不会提前执行失败报告。

## 复用子树时明确数据边界

两段导航执行规则相同，只是目标和结果条目不同，因此可以共用 `NavigateLeg` 这份 XML 定义。它在每次调用时创建不同的节点对象和局部 Blackboard，内部的 `target`、`reached` 名称可以相同，再分别连接到主树的不同条目。

```text
主树 Blackboard                         第一次 NavigateLeg 的局部 Blackboard
pickup_goal = loading_area   ──映射──→   target
pickup_reached               ←─映射──   reached

主树 Blackboard                         第二次 NavigateLeg 的局部 Blackboard
dropoff_goal = unloading_area ─映射──→   target
dropoff_reached              ←─映射──   reached
```

本篇使用官方 3.8 端口映射教程中的普通 **`SubTree`** 写法：

```xml
<SubTree ID="NavigateLeg" target="pickup_goal" reached="pickup_reached"/>
```

这里属性名 `target`、`reached` 是子树局部 Blackboard 的键，属性值 `pickup_goal`、`pickup_reached` 是父 Blackboard 的键名。它们建立映射关系，子树对 `reached` 的写入会反映到主树的 `pickup_reached`。

| 所在位置 | 写法 | 含义 |
| --- | --- | --- |
| 普通节点端口 | `goal="{target}"` | 从当前 Blackboard 的 `target` 读取输入 |
| 3.8 的普通 `SubTree` 边界 | `target="pickup_goal"` | 将子树的 `target` 映射到父树的 `pickup_goal` |
| 普通节点的输出端口 | `reached_goal="{reached}"` | 写入当前 Blackboard 的 `reached`，再由映射连接到父树 |

**不要把本篇 `SubTree` 的映射值改成 `{pickup_goal}`。** 3.8.7 的普通 `SubTree` 分支直接把属性值当作父键名，不会替你去掉花括号，之后就可能找不到正确输入。源码中还提供了使用不同映射语义的 `SubTreePlus`，本篇统一使用普通 `SubTree`，按表中的边界规则填写。

子树边界的键名也不等于 C++ 叶节点的端口名。本例经过的是：`goal` 端口 → 局部 `target` → 父树 `pickup_goal`，每一层分别声明自己的接口。

## 建立组合任务工程

本篇直接复制整个 `bt_running` 文件夹，再把副本重命名为 `bt_mission`，保留原来的持续任务工程供后续对照。

在系统文件管理器中完成下面几步：

1. 打开 `bt_running` 所在的父目录，复制并粘贴整个文件夹，将副本重命名为 `bt_mission`，让两个工程位于同一层目录。

`src/main.cpp` 和 `trees/mission.xml` 已经随工程复制过来，稍后用本篇内容替换。

```text

├── CMakePresets.json
```

## 实现任务所需的节点

导航节点沿用上一篇的生命周期，在此基础上增加“前几次尝试失败”的模拟参数，以及成功后写出到达目标的输出端口。

| 节点 | 类型 | 主要职责 |
| --- | --- | --- |
| `BatteryOK` | `ConditionNode` | 读取电量，达到 30 时返回成功 |
| `ChargeBattery` | `SyncActionNode` | 将模拟电量更新为 80 |
| `NavigateToGoal` | `StatefulActionNode` | 分多次检查导航，成功时写出 `reached_goal` |
| `ReportMission` | `SyncActionNode` | 读取两段导航的结果并报告完成 |
| `ReportFailure` | 简单同步动作 | 输出失败信息，表示报告动作已执行 |

用以下完整程序替换 `src/main.cpp` 的原有内容，再保存。四个节点类和一个简单动作都在这个文件中，方便先把组合任务跑通。

```cpp
#include "behaviortree_cpp_v3/bt_factory.h"

#include <chrono>
#include <cmath>
#include <iostream>
#include <stdexcept>
#include <string>

class BatteryOK : public BT::ConditionNode
{
public:
    BatteryOK(const std::string& name, const BT::NodeConfiguration& config)
        : BT::ConditionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {BT::InputPort<double>("level")};
    }

    BT::NodeStatus tick() override
    {
        auto level = getInput<double>("level");
        if (!level)
        {
            throw BT::RuntimeError("Cannot read input [level]: ", level.error());
        }
        if (!std::isfinite(level.value()) || level.value() < 0.0 || level.value() > 100.0)
        {
            throw std::runtime_error("battery level must be between 0 and 100");
        }
        const auto result = level.value() >= 30.0
                                ? BT::NodeStatus::SUCCESS : BT::NodeStatus::FAILURE;
        std::cout << "[BatteryOK] level=" << level.value()
                  << " -> " << BT::toStr(result) << '\n';
        return result;
    }
};

class ChargeBattery : public BT::SyncActionNode
{
public:
    ChargeBattery(const std::string& name, const BT::NodeConfiguration& config)
        : BT::SyncActionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {BT::OutputPort<double>("level")};
    }

    BT::NodeStatus tick() override
    {
        // 本例把充电简化为一次数据更新，真实充电应实现为持续任务。
        auto written = setOutput("level", 80.0);
        if (!written)
        {
            throw BT::RuntimeError("Cannot write output [level]: ", written.error());
        }
        std::cout << "[ChargeBattery] level=80\n";
        return BT::NodeStatus::SUCCESS;
    }
};

class NavigateToGoal : public BT::StatefulActionNode
{
public:
    NavigateToGoal(const std::string& name, const BT::NodeConfiguration& config)
        : BT::StatefulActionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {BT::InputPort<std::string>("goal"),
                BT::InputPort<int>("ticks", 2, "每次导航尝试的检查次数"),
                BT::InputPort<int>("fail_attempts", 1, "模拟前几次尝试失败"),
                BT::OutputPort<std::string>("reached_goal")};
    }

    BT::NodeStatus onStart() override
    {
        auto goal = getInput<std::string>("goal");
        auto ticks = getInput<int>("ticks");
        auto failures = getInput<int>("fail_attempts");
        if (!goal)
        {
            throw BT::RuntimeError("Cannot read input [goal]: ", goal.error());
        }
        if (!ticks)
        {
            throw BT::RuntimeError("Cannot read input [ticks]: ", ticks.error());
        }
        if (!failures)
        {
            throw BT::RuntimeError("Cannot read input [fail_attempts]: ", failures.error());
        }
        if (goal.value().empty() || ticks.value() < 1 || failures.value() < 0)
        {
            throw std::runtime_error("invalid navigation simulation parameters");
        }

        goal_ = goal.value();
        required_ticks_ = ticks.value();
        failed_attempts_ = failures.value();
        completed_ticks_ = 0;
        // 每个节点实例分别保留尝试次数，用于模拟先失败、后成功。
        ++attempt_;
        std::cout << "[NavigateToGoal] start goal=" << goal_
                  << ", attempt=" << attempt_ << '\n';
        return BT::NodeStatus::RUNNING;
    }

    BT::NodeStatus onRunning() override
    {
        if (++completed_ticks_ < required_ticks_)
        {
            return BT::NodeStatus::RUNNING;
        }
        if (attempt_ <= failed_attempts_)
        {
            std::cout << "[NavigateToGoal] failed goal=" << goal_
                      << ", attempt=" << attempt_ << '\n';
            return BT::NodeStatus::FAILURE;
        }

        auto written = setOutput("reached_goal", goal_);
        if (!written)
        {
            throw BT::RuntimeError("Cannot write output [reached_goal]: ", written.error());
        }
        std::cout << "[NavigateToGoal] arrived goal=" << goal_
                  << ", attempt=" << attempt_ << '\n';
        return BT::NodeStatus::SUCCESS;
    }

    void onHalted() override
    {
        std::cout << "[NavigateToGoal] halted goal=" << goal_ << '\n';
        completed_ticks_ = 0;
    }

private:
    std::string goal_;
    int required_ticks_ = 0;
    int completed_ticks_ = 0;
    int failed_attempts_ = 0;
    int attempt_ = 0;
};

class ReportMission : public BT::SyncActionNode
{
public:
    ReportMission(const std::string& name, const BT::NodeConfiguration& config)
        : BT::SyncActionNode(name, config)
    {}

    static BT::PortsList providedPorts()
    {
        return {BT::InputPort<std::string>("pickup"),
                BT::InputPort<std::string>("dropoff")};
    }

    BT::NodeStatus tick() override
    {
        auto pickup = getInput<std::string>("pickup");
        auto dropoff = getInput<std::string>("dropoff");
        if (!pickup)
        {
            throw BT::RuntimeError("Cannot read input [pickup]: ", pickup.error());
        }
        if (!dropoff)
        {
            throw BT::RuntimeError("Cannot read input [dropoff]: ", dropoff.error());
        }
        std::cout << "[ReportMission] pickup=" << pickup.value()
                  << ", dropoff=" << dropoff.value() << '\n';
        return BT::NodeStatus::SUCCESS;
    }
};

BT::NodeStatus ReportFailure(BT::TreeNode&)
{
    std::cout << "[ReportFailure] transport mission failed\n";
    return BT::NodeStatus::SUCCESS;
}

int main()
{
    try
    {
        BT::BehaviorTreeFactory factory;
        factory.registerNodeType<BatteryOK>("BatteryOK");
        factory.registerNodeType<ChargeBattery>("ChargeBattery");
        factory.registerNodeType<NavigateToGoal>("NavigateToGoal");
        factory.registerNodeType<ReportMission>("ReportMission");
        factory.registerSimpleAction("ReportFailure", ReportFailure);

        auto blackboard = BT::Blackboard::create();
        blackboard->set("battery", 20.0);
        blackboard->set("pickup_goal", std::string("loading_area"));
        blackboard->set("dropoff_goal", std::string("unloading_area"));
        auto tree = factory.createTreeFromFile(BT_XML_PATH, blackboard);

        BT::NodeStatus result = tree.tickRoot();
        while (result == BT::NodeStatus::RUNNING)
        {
            tree.sleep(std::chrono::milliseconds(100));
            result = tree.tickRoot();
        }
        std::cout << "Tree result: " << BT::toStr(result) << '\n';
        if (result == BT::NodeStatus::SUCCESS)
        {
            std::cout << "[main] pickup_reached="
                      << blackboard->get<std::string>("pickup_reached") << '\n';
            std::cout << "[main] dropoff_reached="
                      << blackboard->get<std::string>("dropoff_reached") << '\n';
        }
        return result == BT::NodeStatus::SUCCESS ? 0 : 1;
    }
    catch (const std::exception& error)
    {
        std::cerr << "Error: " << error.what() << '\n';
        return 2;
    }
}
```

`ticks` 和 `fail_attempts` 都是本例的模拟参数。`ticks="2"` 表示一次导航在两次 `onRunning()` 检查后给出结果；`fail_attempts="1"` 表示同一个节点实例的第一次尝试失败，后续尝试成功。节点的 `attempt_` 从 `0` 开始，在每次 `onStart()` 中递增。

`attempt_` 是教学模拟器自己的计数，和 Retry 装饰节点内部的重试计数不是同一个变量。这里故意保留它，才能在重启导航后模拟“第一次失败、第二次成功”。每次 Launch 都会创建新的树；如果实际程序复用同一棵树处理多个任务，应明确什么时候重置业务成员和结果条目。

### 对照本例中的 API 参数

本篇主要组合前面已经使用过的接口。注册和端口接口的原型见 [第一个完整程序](1200-0400-0200-0300-第一个完整程序.md)，外部 Blackboard 的读写见 [节点之间传数据](1200-0400-0200-0400-节点之间传数据.md)，回调与驱动循环见 [持续任务与中止](1200-0400-0200-0500-持续任务与中止.md)。对照本例时，重点看每个实参对应哪一层名称：

| 调用 | 参数含义 | 返回值 |
| --- | --- | --- |
| `factory.registerNodeType<NavigateToGoal>("NavigateToGoal")` | 模板参数是 C++ 节点类；第一个函数参数是 XML 中使用的注册名 | `void`，注册类型，尚未启动导航 |
| `factory.registerSimpleAction("ReportFailure", ReportFailure)` | 第一个参数是注册名；第二个参数是回调函数本身，树执行到 `<ReportFailure/>` 时才调用它 | 注册函数返回 `void`；回调另行返回自己的节点状态 |
| `blackboard->set("battery", 20.0)` | 第一个参数是 Blackboard 键，第二个参数是值；这里省略 `<double>`，由 `20.0` 推导类型 | `void`，写入电量 |
| `factory.createTreeFromFile(BT_XML_PATH, blackboard)` | 第一个参数是入口 XML 路径；第二个参数是根树使用的 Blackboard 共享指针 | `BT::Tree`，包含创建好的节点实例 |
| `setOutput("reached_goal", goal_)` | 第一个参数是当前节点的输出端口名；第二个参数是保存的目标字符串 | `BT::Result`，本例检查写出是否成功 |
| `blackboard->get<std::string>("pickup_reached")` | 模板参数指定读取类型；第一个函数参数是根 Blackboard 中的结果键 | `std::string` 值；键不存在或类型不兼容时抛出异常 |

`setOutput()` 的 `reached_goal` 是节点端口名，`get()` 的 `pickup_reached` 是主程序要读取的 Blackboard 键，两者由后面的 XML 映射连接。`ReportFailure()` 回调返回 `SUCCESS` 表示报告动作完成；整项运输任务的失败结果由 XML 中包裹它的 `ForceFailure` 保留，不能把回调返回值与注册函数返回值混为一谈。

## 用两个 XML 文件组织任务

### trees/mission.xml

用下面的 XML 替换 `trees/mission.xml` 的原有内容，再保存。

```xml
<root main_tree_to_execute="MainTree">
    <include path="navigation.xml"/>

    <BehaviorTree ID="MainTree">
        <Sequence name="transport_job">
            <Fallback name="ensure_battery">
                <BatteryOK level="{battery}"/>
                <ChargeBattery level="{battery}"/>
            </Fallback>

            <Fallback name="run_or_report_failure">
                <Sequence>
                    <SubTree ID="NavigateLeg"
                             target="pickup_goal" reached="pickup_reached"/>
                    <SubTree ID="NavigateLeg"
                             target="dropoff_goal" reached="dropoff_reached"/>
                    <ReportMission pickup="{pickup_reached}"
                                   dropoff="{dropoff_reached}"/>
                </Sequence>
                <ForceFailure>
                    <ReportFailure/>
                </ForceFailure>
            </Fallback>
        </Sequence>
    </BehaviorTree>
</root>
```

主树中两次 `SubTree` 使用相同的 `ID="NavigateLeg"`，但分别映射到取货点和放货点的父键。`NavigateLeg` 是 XML 中定义的行为树名称，`NavigateToGoal` 才是注册到工厂的 C++ 叶节点名称。

### trees/navigation.xml

将下面的内容保存到新建的 `trees/navigation.xml`。

```xml
<root>
    <BehaviorTree ID="NavigateLeg">
        <RetryUntilSuccessful num_attempts="2">
            <NavigateToGoal goal="{target}" reached_goal="{reached}"
                            ticks="2" fail_attempts="1"/>
        </RetryUntilSuccessful>
    </BehaviorTree>
</root>
```

`<include path="navigation.xml"/>` 会在加载主 XML 时引入子树定义，路径相对于包含它的 `mission.xml` 所在目录。主程序通过 `BT_XML_PATH` 的完整路径加载入口，所以从不同工作目录启动，仍能找到同目录的 `navigation.xml`。

C++ 中已经注册了叶节点；两个 XML 负责定义和连接任务。工厂加载入口文件时会处理 `include` 和 `BehaviorTree ID`，因此不需要再为 `NavigateLeg` 编写一个 C++ 节点类。

```text
[ChargeBattery] level=80
[NavigateToGoal] start goal=loading_area, attempt=1
[NavigateToGoal] failed goal=loading_area, attempt=1
[NavigateToGoal] start goal=loading_area, attempt=2
[NavigateToGoal] arrived goal=loading_area, attempt=2
[NavigateToGoal] start goal=unloading_area, attempt=1
[NavigateToGoal] failed goal=unloading_area, attempt=1
[NavigateToGoal] start goal=unloading_area, attempt=2
[NavigateToGoal] arrived goal=unloading_area, attempt=2
[ReportMission] pickup=loading_area, dropoff=unloading_area

[main] pickup_reached=loading_area
[main] dropoff_reached=unloading_area
```

> **截图预留：组合任务正常完成。** 展示从电量不足、模拟充电、两段导航分别重试，到主程序读取结果的完整输出。

初始电量为 20，因此先检查失败，再由 `ChargeBattery` 更新为 80。两段导航分别经历第一次失败、第二次成功，最后 `ReportMission` 和主程序都能读到两个到达结果。

| 执行位置 | 本次使用的数据 | 结果 |
| --- | --- | --- |
| 电量 Fallback | 主树的 `battery` | 低电量时更新到 80 |
| 第一次 NavigateLeg | `pickup_goal` 映射到局部 `target` | 写出 `pickup_reached` |
| 第二次 NavigateLeg | `dropoff_goal` 映射到另一个局部 `target` | 写出 `dropoff_reached` |
| ReportMission | 主树的两个结果键 | 输出任务完成信息 |
| main | 从根 Blackboard 读取两个结果 | 确认跨子树的数据传递 |

电量检查是这次任务的启动准备。进入导航后，外层普通 Sequence 会从正在执行的位置继续，电量检查不会每次都重跑。如果任务要求导航期间持续检查某个条件，可以沿用上一篇的 ReactiveSequence 方式组织检查层。

## 有限重试与失败报告各自负责一层

`num_attempts="2"` 表示**最多两次总尝试**，不是首次尝试之后再额外重试两次。导航返回 `RUNNING` 时，装饰节点继续等待这一次尝试；只有导航返回 `FAILURE`，才会记录一次失败并决定是否重新开始。

在 3.8.7 中，Retry 收到失败后可以在同一次根 tick 内重置子节点并立即开始下一次尝试。本例新的 `onStart()` 返回 `RUNNING` 后，控制权就会回到主循环。因此日志中一次失败后可以紧接着出现下一次 `start`，不必假定它们一定属于不同的根 tick。

将 `navigation.xml` 中的 `num_attempts="2"` 改为 `num_attempts="1"`，只保存 XML，再点击 **Launch**。此时第一次失败已经耗尽次数，输出为：

```text
[BatteryOK] level=20 -> FAILURE
[ChargeBattery] level=80
[NavigateToGoal] start goal=loading_area, attempt=1
[NavigateToGoal] failed goal=loading_area, attempt=1
[ReportFailure] transport mission failed
Tree result: FAILURE
```

没有出现放货点导航，也没有执行 `ReportMission`，因为第一段子树失败后，导航 Sequence 立即结束。

> **截图预留：重试次数耗尽。** 展示 `num_attempts="1"`、失败报告以及最终的 `FAILURE`。

失败报告分支外面包了一层 `ForceFailure`：

```text
ForceFailure
└── ReportFailure   报告动作执行完毕，返回 SUCCESS
         ↓
该分支向任务 Fallback 返回 FAILURE
```

`ReportFailure` 返回成功表示日志报告已经执行；`ForceFailure` 保留的是运输任务失败的结果。这样完成失败处理后，整棵树仍返回 `FAILURE`，主程序也不会进入成功结果的读取分支。

## 分别修改电量、重试和映射来对照

每次对照只改一项，完成后恢复原值，再进行下一项。修改 C++ 后先 **Build → Launch**；只改 XML 时保存后直接 **Launch**。

| 修改位置 | 修改内容 | 观察到的结果 |
| --- | --- | --- |
| `main()` 初始化 | `battery` 从 20.0 改为 80.0 | 电量检查直接成功，不执行模拟充电 |
| `navigation.xml` | `fail_attempts` 从 1 改为 0 | 两段导航都在第一次尝试成功 |
| `navigation.xml` | 保持最多两次尝试，将 `fail_attempts` 改为 2 | 取货点两次都失败，任务失败，放货点不执行 |

## 在断点中确认两次调用是不同的节点实例

恢复主示例的电量与 XML，先 **Build**。在 `NavigateToGoal::onStart()` 中 `++attempt_` 之后的打印语句处设置断点，再点击 **Debug**。

每次暂停时查看 `goal_`、`attempt_`，并比较 `this` 指针。取货点的两次启动会在同一个节点对象上出现，尝试次数依次为 1、2；进入放货点时，`this` 指针不同，那个节点自己的尝试次数也从 1 开始。

这个过程对应的是“同一份子树定义，两次独立实例化”。复用的是结构和实现，任务成员与未映射的局部 Blackboard 条目分别属于各自实例。
