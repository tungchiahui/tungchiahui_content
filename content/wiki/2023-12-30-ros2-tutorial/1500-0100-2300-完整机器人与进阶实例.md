> 单执行器跑通以后，才扩展为完整机器人。框架接口可以复用，设备层仍要按实际结构设计。

## 示例 1：从一个执行器扩展为双关节

先把固定数组改成与 HardwareInfo 一致的预分配存储，再验证每个关节的名称、方向、范围和设备地址。完成所有反馈校验后，再统一发布整组快照。

```text
逻辑 joint1 → 设备地址 A → 参数、方向、零点 A
逻辑 joint2 → 设备地址 B → 参数、方向、零点 B
```

映射必须显式存在，不能依赖串口先收到谁就把谁视为第一个关节。多设备反馈不同时到达时，快照还应记录每个设备的时效和有效性。

### 什么情况下使用一个 System

如果下位机一次收发整台机器人的关节数据，一个 System 通常更符合通信边界。如果每个执行器独立通信、独立启停，则需要结合 Actuator 的生命周期和故障隔离方式设计。

## 示例 2：从单轮扩展为差速底盘

沿用[差速底盘物理仿真](/wiki/2023-12-30-ros2-tutorial/1500-0100-1600-cha-su-di-pan-wu-li-fang-zhen)的控制器配置语义：左、右轮 velocity 命令，position/velocity 反馈，单位为输出轮轴 rad 和 rad/s。

先分别验证两个轮子的正方向，再验证同号命令对应前进；随后标定轮半径和有效轮距。真实底盘中，结构误差和打滑可能让理想模型参数不足以得到准确里程计。

`open_loop: false` 表示使用反馈计算里程计，但编码器里程计仍可能漂移。后续定位融合属于另一个学习阶段，不在本教程中假装已经完成。

## 示例 3：只构建当前学习的进阶实例

以传动实例为例，在 source 系统 Humble 的新终端中执行：

```bash
cd ~/ros2_control_demos_ws
rosdep install --from-paths src \
  --ignore-src -r -y --rosdistro humble
colcon build --symlink-install --packages-up-to ros2_control_demo_example_8 \
  --cmake-args -DBUILD_TESTING=OFF
source install/setup.bash
```

接下来先查看包中实际安装的 launch 文件，再选择文件名：

```bash
ls $(ros2 pkg prefix ros2_control_demo_example_8)/share/ros2_control_demo_example_8/launch
# 选择上面实际存在的启动文件后，再使用 ros2 launch 包名 文件名 --show-args。
```

不要把某个其它发行版的命令直接搬过来。先阅读当前固定提交中该实例的 doc/userdoc.rst，确认依赖与使用方法。

## 多机器人最常见的命名问题

Topic namespace、关节名称前缀、TF frame 名称、硬件组件名称是不同维度。把节点放到 namespace 下面，不会自动给 URDF 中所有关节与 frame 改名。
