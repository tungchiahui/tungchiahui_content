## MID360与TF联调

### 检查TF的生成情况

启动`robot_description`，里面有`joint_state_publisher，robot_state_publisher，RViz2`：

```bash
source install/setup.bash
ros2 launch robot_description robot_description_launch.py \
  robot_name:=reality_robot \
  use_sim_time:=false \
  use_rviz:=true
```

这里需要显式设置 `robot_name:=reality_robot`，因为描述包自身的默认入口仍是 `default_value="simulation_robot"`。
然后`use_rviz`默认就是`true`，可以不加。

启动串口程序发布`/serial/gimbal_joint_state`

```bash
source install/setup.bash
ros2 launch serial_comm serial_comm.launch.py
```

出现问题，雷达的hz特别的小：

这个现象很像不是 Mid360 真掉到 3 Hz，而是 RELIABLE 大点云被远端订阅者拖慢了。
这版驱动的 /livox/lidar/pointcloud publisher 是默认 QoS，也就是你前面看到的那种 RELIABLE。一帧约 257 KB，20 Hz 单独 PointCloud2 就约 41 Mb/s。ROS 2 的 DDS/QoS 本身支持不同可靠性策略；对这类高频传感器数据，让显示/调试端用“允许丢旧帧、优先拿最新帧”的方式通常更合适。ROS Documentation
而且一个慢的远程 RELIABLE reader，可能让 writer 做重传、排队甚至产生反压。于是你会看到一个很反直觉的现象

```text
电脑/RViz 收得慢
       ↓
RELIABLE 重传/积压
       ↓
工控机 publisher 也被拖住
       ↓
连工控机本地 ros2 topic hz 看起来都只剩 3 Hz
```

解决方案：

详见[ROS 2 远端查看 MID360 点云导致降频、延迟和 RViz 不显示](/wiki/2026-09-20-dao-hang/0600-kai-fa-wen-ti-yu-pai-cha#ros-2-远端查看-mid360-点云导致降频-延迟和-rviz-不显示)


#### 联合TF测试下是否整套是否成功

总体框架就是：
- `livox_ros_driver2`和 `serial_comm` 由工控机开启。
- `robot_state_publisher` 由电脑或者工控机开启。

```bash
                    工控机
STM32
  ↓
serial_comm
  ↓
/serial/gimbal_joint_state
             │
             │ DDS
             ▼
                    电脑
joint_state_publisher
  ↓
/joint_states
  ↓
robot_state_publisher
  ↓
TF
chassis → gimbal_yaw_odom → front_mid360


Mid360
  ↓ Ethernet
livox_ros_driver2        （工控机）
  ↓
/livox/lidar
/livox/lidar/pointcloud
/livox/imu
             │
             │ DDS
             ▼
           RViz          （电脑）
```


工控机：

```bash
source install/setup.bash
ros2 launch livox_ros_driver2 msg_MID360_launch.py
```

```bash
source install/setup.bash
ros2 launch serial_comm serial_comm.launch.py
```

电脑：

```bash
source install/setup.bash
ros2 launch robot_description robot_description_launch.py \
  robot_name:=reality_robot \
  use_sim_time:=false \
  use_rviz:=true
```

RViz 的 Fixed Frame 理解成 “我站在哪个坐标系里看整个世界？”
而点云坐标系是`frame_id = front_mid360`，
也就是说，每一帧原始点云都是“以雷达自身为原点”描述的。

| RViz Fixed Frame | 你转云台 yaw 时 | 你整车移动时 |
|---|---|---|
| `front_mid360` | **环境点云会动/转** | 环境也会动 |
| `chassis` | **环境应基本不动** | 环境会动 |
| `odom` / `map` | 环境应基本不动 | 有正确里程计/定位后，环境也应基本不动 |
